# E1 v2定向预检：长C2超时与v3候选

## 结论

`E1-RUNTIME-V2-PREFLIGHT-001`为非正式定向预检，覆盖全局顺序12–21共10条任务。
其中9条成功、1条失败，因此v2不得冻结为正式B01运行时。采集器的`collector_stop`自动停止流程
通过：Windows raw包含`control=1`及三项invalid均为0；但实验开始前重复发送一次`idle_end`，所以
marker为23（正常构成为10×2查询边界加1组idle边界，即22；额外1条是已识别的重复idle结束标记）。
该raw只能作为非正式运行时预检证据，不能进入正式E1能耗统计。

## 失败任务与服务证据

唯一失败为run order 21：`formal_exp_0171:C2:2`，客户端记录的`latency_ms=300395.3211830012`，
错误为`llama-server request failed: timed out`。此时服务固定`--parallel 1`，日志中没有KV cache、
HTTP 500或context-size错误，说明v2已经消除了B01-002的并发KV级联故障。

服务任务1423在取消前已生成500 token，生成速率约2.58 token/s；其后约1.5秒发生客户端取消，
而C2生成上限为512 token。日志显示取消后slot正常释放且所有slot空闲。故本次直接原因是300秒
超时缺乏最慢C2尾部余量，不是上下文溢出，也不应被解释为C2无法完成。

运行结束后`pgrep`为空、`/health`连接被拒绝；但服务日志止于正常idle状态，未记录fatal、OOM或
cleanup。内核日志读取受权限限制，故服务后来消失的原因登记为`unresolved_lifecycle_event`，不得
未经证据归因于模型崩溃。
