## 哈希异常与勘误

初始冻结记录把Windows CRLF工作树字节哈希
`12AC88CDD2C694BD0413D59E33D58854487A1ECD5268AC6E95A61B121904170A`写为配置SHA-256。Radxa clean
工作树中的同一Git blob使用LF，实测为
`C95E890830FB34853DDA40D6E23B26F6C9AB25AB82E1C136B40D76B64FC85729`。本地将CRLF逐字节规范化为LF后
得到同一`C95E...5729`，且`git diff --ignore-space-at-eol`为空，证明JSON文本内容未变。

处理方式：

1. 在`.gitattributes`固定`/configs/E1_devtemp_v1.json text eol=lf`；
2. 机器可读摘要和冻结日志改用LF字节SHA-256；
3. 保留旧CRLF哈希及其错误来源，不把它静默删除；
4. 不重新生成315行任务清单，不改变seed、run order、配置参数、查询或批次边界。

## 下一动作与停止规则

提交并同步本勘误后，Radxa必须再次确认配置SHA-256为`C95E...5729`、正式清单仍为`D2BE...0048`、
