## 2. 研究题目

中文：

> 资源受限边缘设备上离线应急RAG的校准安全约束逐查询配置选择

英文：

> Calibrated Safety-Constrained Per-Query Configuration Selection for
> Offline Emergency RAG on a Resource-Constrained Edge Device

## 3. 主任务范围

### 3.1 四个宏观任务域

| 编号 | 主任务域 | 纳入场景 |
|---|---|---|
| D1 | 地震与结构性危险 | 地震、余震、坍塌、被困、挤压、骨折和相关创伤 |
| D2 | 火灾与烟气危险 | 建筑/高层火灾、烟气暴露、撤离、避险和等待救援 |
| D3 | 洪涝与基础服务中断 | 洪水、暴雨、内涝、滑坡关联风险、断电断网、饮水安全 |
| D4 | 极端暴露与跨灾种公众急救 | 高低温、雷电、道路结冰、头伤、出血、窒息、中毒、溺水等公众急救 |

心理稳定、设备低电量、证据不足、辖区不明和域外请求作为跨域挑战条件，
不单独扩展为第五个主任务域。

### 3.2 不纳入范围

- 临床诊断、处方或个体治疗决策；
- 自动疏散命令和真实救援资源调度；
- 面向公众的无人审核应急广播；
- 云端API或联网检索；
- 真实救援成功率；
- 所有边缘设备的一般化结论。

## 4. 语言范围

- 中文口语、短查询、错别字和输入噪声可进入挑战集；
- 英文或多语言实验不属于本版本确认性研究；
- 若后续获得独立英文协议库和查询集，只能作为协议修订后的探索性外部测试；

## 5. 数据规模与分区

### 5.1 当前400条的状态

现有400条是协议约束、研究者编写并完成双审仲裁的场景型开发gold：

- 用于标注规则、schema、代码、检索和路由工程开发；
- 可在重新分组后进入最终`train`；
- 不得进入最终`cal_op`、`cal_ch`、`test_op`或`test_ch`；
- 其L3、C3和域外比例是设计配额，不代表真实发生率；
- 已运行的Windows抽取式工程验证不属于论文结果。

### 5.2 最终核心数据规模

冻结核心基础查询数为3,600条：

| 分区 | 数量 | 用途 |
|---|---:|---|
| `train` | 1,000 | 模型拟合、归一化和类别权重 |
| `valid` | 200 | 早停、普通超参数和checkpoint选择 |
| `cal_op` | 800 | 运营/准自然分布的主安全校准 |
| `cal_ch` | 200 | 挑战诊断和分组校准，不选择主阈值 |
| `test_op` | 1,200 | 唯一确认性最终测试 |
| `test_ch` | 200 | 高风险、偏移和域外挑战报告 |
| 合计 | 3,600 | 不含扰动派生和可选外部测试 |

选择1,200条`test_op`的依据是：在配对不一致率6%、目标风险差2个百分点、
双侧`alpha_test=0.05`时，约能达到80%功效。1,600条对应约90%功效，
本研究不将其设为强制规模；若资源允许增加，只能在查看正式测试结果前登记修订。

现有400条可计入1,000条`train`，因此至少还需构建3,200条独立基础查询。

### 5.3 分区构造

- `train/valid/cal/test`必须按事件簇、协议家族、版本链和模板家族整体分组；
- `cal_op/test_op`按预先定义的准自然来源分布构造；
- `cal_ch/test_ch`按高风险、否定冲突、信息不足、协议冲突、资源约束和域外条件构造；
- 不允许只靠随机哈希决定运营集与挑战集身份；
- 同一canonical query、扰动父样本或语义簇不得跨分区；
- `test_op/test_ch`在全部方法、阈值和公平性规则冻结后只正式运行一次。

## 6. 唯一确认性比较

### 6.1 方法

PROPOSED：

> 使用query、知识支持状态和实时设备状态，预测各配置的L3风险与资源需求，
> 经独立校准构造安全接受集合，再从安全且满足资源预算的配置中选择成本最低者；
> 没有可接受生成配置时强制C3。

### 6.2 基线为何具有代表性

本研究不把“所有发表过的 RAG 变体”简单堆叠为基线，而是按部署决策中必须回答的
三个问题组织对照：是否需要检索、是否需要逐查询选择、是否需要安全校准和资源
约束。由此形成从最低成本参考到强固定系统的完整梯度：

| 基线 | 代表的方法家族 | 在本研究中控制的变量 | PROPOSED 相对它的改进含义 |
|---|---|---|---|
| 固定 C0 | 无检索/直接生成 | 同一生成模型、量化、解码和输出上限 | 证明仅依赖模型记忆在协议证据和安全性上不足，并量化检索的必要性 |
| 固定 C1 | 轻量单步 RAG、词法或单阶段检索 | 同一知识库、分块、生成器和查询集 | 证明单次检索虽然降低成本，但不能根据风险、证据状态和设备预算调整配置 |
| **固定强配置 C2** | 增强型混合、多步、协议感知 RAG | 同一协议库、候选规模、过滤/重排规则、生成预算和设备测量 | 这是最严格的确认性挑战：若 PROPOSED 仍能在配对 L3 风险、coverage 和资源上改进，说明收益来自逐查询安全配置选择，而不是换了更强生成器 |
| 固定 C3 | 确定性安全回退/人工升级 | 同一回退话术、回退判定和统计分母 | 给出安全和资源的保守下界，检验 PROPOSED 是否只是通过过度拒答换取低风险 |
| query-only 路由 | 仅依赖查询表面特征的风险路由 | 与 PROPOSED 使用相同训练/校准角色，但不提供知识支持状态和设备状态 | 量化仅看文本难度的不足，验证协议适用性和实时资源状态是否带来独立增益 |
| 未校准路由 | 预测风险但不做独立概率校准 | 同一特征、同一模型容量和训练预算，仅移除校准/风险上界 | 将“有路由”与“风险可控的路由”区分开，检验校准是否真正降低风险越界 |
| 二元安全规则 | 关键词/阈值式保守策略 | 规则只能使用部署时可观测输入，冻结版本和人工开发预算 | 证明 PROPOSED 的收益不是来自任意人工规则，而是来自可学习、可校准的联合选择 |

固定 C2 被选为唯一确认性对照，原因不是它在所有任务上必然最优，而是它代表了
当前离线应急 RAG 中最有竞争力的“固定高质量配置”路线：它已经同时拥有协议
证据检索、适用性过滤、冲突检查和必要的多步处理，但对每条查询使用同一资源
等级。它因此构成对 PROPOSED 最不利且最有解释力的比较：PROPOSED 若只优于 C0
或 C1，不能说明超越强 RAG；只有相对于固定 C2 仍能在相同安全约束下提高服务
覆盖率、降低资源成本或减少风险越界，才能支持“逐查询配置选择”的核心主张。

这些基线覆盖了本任务的主要现有方法机制，但不声称穷尽所有论文实现。外部方法
若使用不同基础模型、不同知识库、额外训练语料或云端工具，应作为“生态参考/官方
复现”单列；若无法在同一离线模型、知识库和资源预算下复现，不得与主比较混合，
否则结果同时反映预训练和部署环境差异。

### 6.3 主比较与次要比较的解释边界

唯一确认性主比较仍为：

> PROPOSED vs 固定强配置 C2，即对所有非域外查询使用同一增强型 RAG 配置。

主比较检验的是“逐查询、校准、安全约束和资源感知”相对于“固定强配置”的联合
价值，不把单一模块的效果误写成整体优势。其他基线用于机制定位：

- PROPOSED vs 固定 C0/C1：检验检索和增强配置是否必要；
- PROPOSED vs query-only：检验知识支持状态和设备状态的增量；
- PROPOSED vs 未校准路由：检验独立校准与风险上界的增量；
- PROPOSED vs 二元安全规则：检验可学习选择是否优于静态规则；
- PROPOSED vs 固定 C3：检查是否通过过度回退获得表面安全。

这些比较属于关键次要或探索性分析，不与主比较共同消耗主要检验的显著性水平。

两种方法必须使用：

- 相同本地生成模型和量化版本；
- 相同最大输出长度和解码参数；
- 相同协议库版本；
- 相同查询顺序区组；
- 相同设备状态测量规则；
- 相同输出级双审和仲裁流程。

## 7. 主要终点与检验

### 7.1 唯一确认性主终点

每条`test_op`查询对应一个二元L3严重失效结局。主效应量为：

```text
RD_L3 = P(L3 | PROPOSED) - P(L3 | fixed C2)
```

主假设：

- H0：两种方法的配对L3失效概率相同；
- H1：PROPOSED的配对L3失效概率低于固定C2。

主分析：

- 配对McNemar检验；
- 双侧`alpha_test=0.05`；
- 同时报告绝对风险差、风险比和95%置信区间；
- 以`source_group_id`进行group bootstrap敏感性分析；
- 失败、超时、OOM和空输出保留并按预注册规则计入。

### 7.2 安全校准参数

```text
alpha_risk = 0.05
delta_total = 0.05
delta_per_generated_configuration = 0.05 / 3
split_seed = 42
train_seeds = [11, 23, 37, 51, 71]
generation_seeds = [101, 103, 107]
order_seeds = [211, 223, 227]
```

`alpha_test`是统计检验显著性水平，`alpha_risk`是允许的严重失效风险上限，
二者不得混用。

## 8. 指标层级

### 8.1 主要指标

- 查询级L3严重失效二元标签；
- PROPOSED与固定C2的配对L3风险差。

### 8.2 关键次要指标

按以下顺序报告，不替代主要结局：

1. 校准风险上界和实际风险越界率；
2. E1上的物理焦耳/到达查询；
3. E1上的P95端到端时延；
4. 服务覆盖率和不安全接受率；
5. 必需行动完整率与禁止行动违反率；
6. C3回退正确率和错误降级率。

资源优越性只在安全门通过的方法之间解释。

### 8.3 次要指标

- 峰值RSS、平均/峰值功率、温度和热降频；
- 首token时延、吞吐和路由器净开销；
- gold evidence Recall@k；
- 证据、辖区、版本和适用性一致率；
- 资源预测MAE/MAPE和风险校准误差。

### 8.4 探索性指标

- 四个主任务域、L3子类和查询类型切片；
- 否定、多意图、噪声、协议冲突和错误辖区；
- 冷启动、热稳态和持续负载；
- 温度缩放、Platt、等距回归和CRC比较；
- 少样本重校准、外部数据和可选第二设备；
- 消融、Pareto前沿和失败类型矩阵。

探索性结果不用于修改主要假设。

## 9. 数据与参与者边界

本版本不纳入：

- 真实参与者实验；
- 真实患者、未成年人或一线救援人员数据；
- 真实应急通话、聊天或定位记录；
- 姓名、手机号、地址、精确坐标、病历或其他可识别信息；
- 需要知情同意才能获取的数据。

正式数据仅来自：

- 已审计权威协议；
- 许可证允许的公开灾害文本，仅用于语言和场景分布；
- 研究者编写并双审的协议约束查询；
- 去标识、无个人数据的公开或准真实查询。

若后续加入真实用户或敏感数据，必须升级主版本、重新确定伦理路径，
且不得混入当前确认性数据。
