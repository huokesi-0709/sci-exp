## 为什么尚未正式锁定

模型文件只有约388 MiB，但实际内存还包括权重映射、KV缓存、运行时工作区、
检索器和项目进程。没有E1的总内存与可用内存，不能仅凭文件大小确定4096上下文
是否稳定。`llama-server`也必须在E1的真实ARM64系统上构建，才能锁定动态依赖、
构建参数和二进制哈希。

本地GGUF元数据没有提供量化发布仓库或转换提交。基础模型许可已经核对为
Tongyi Qianwen Research License，内部非商业研究可以继续；但在补齐派生GGUF来源
前，不把该文件对外再分发。

## E1上线后的唯一执行入口

在Windows PowerShell中运行：

```powershell
powershell -ExecutionPolicy Bypass -File `
  D:\projects\RAG-sci\docs\sci-exp\scripts\复制并探测E1.ps1 `
  -E1Host <E1当前IP或主机名> -User radxa
```

脚本遇到已存在的`/home/radxa/sci-exp`会停止，不会覆盖设备上的旧目录。
探测结果会自动回收到Windows的`data/logs`。

取得探测结果后，只有满足以下条件才运行
`scripts/构建并锁定ARM64_llama_server.sh`：

- `machine`为`aarch64`或`arm64`；
- E1剩余存储足以容纳源码构建目录和二进制；
- RAM预算支持候选模型、冻结上下文和检索进程并行存在；
- 已决定使用板载功率路径还是外置功率计。
