# 重复实验与置信区间报告方案

## 1. 适用情形

当以下信息尚不稳定时，严格样本量计算可能不可信：

- L3 严重失效基准率未知；
- PROPOSED 与基线的配对不一致率未知；
- 行动完整率和能耗差异分布明显偏态；
- 热降频造成会话内相关；
- C3 coverage 导致有效接受样本量不固定；
- 灾种、语言和协议版本之间差异较大。

此时不应根据任意乐观效应量给出一个看似精确的样本数。建议采用“固定最低规模+
多层重复+预注册置信区间”的策略，使结果的抽样、训练、生成和设备测量不确定性均
可见。

## 2. 统计单位

不同结局使用不同独立单位：

| 结局 | 主要统计单位 | 不能当作独立单位的重复 |
| --- | --- | --- |
| L3、行动完整率、回退 | 查询或 `source_group_id` | 同查询的配置、seed和重复运行 |
| 配置间差异 | 同一查询的配对结果 | 将两方法当作独立样本 |
| 时延、能耗、内存 | 查询×独立设备会话 | 同一连续会话内相邻请求 |
| 热退化 | 独立设备会话 | 同一会话内的所有迭代 |
| 训练稳定性 | 独立训练seed | 同一checkpoint的重复推理 |
| 校准稳定性 | 独立校准重采样/分割 | 在同一校准集重复运行相同代码 |

所有 bootstrap 应以查询组或设备会话为单位，而不是以 JSONL 行为单位。

## 3. 需要区分的五类不确定性

### 3.1 查询抽样不确定性

不同查询、灾种、语言和协议来源会改变方法效果。使用 group-level bootstrap 和固定
测试集估计。

### 3.2 训练不确定性

神经网络初始化、batch 顺序和负样本采样可能改变结果。使用多个训练 seed 估计。

### 3.3 生成不确定性

随机解码或后端非确定性会改变答案。使用配对 generation seed 估计。

### 3.4 校准不确定性

有限校准集会使接受阈值和 coverage 波动。使用配置级精确风险上界和校准重采样
估计。

### 3.5 设备测量不确定性

温度、缓存、后台负载和功率测量会导致资源波动。使用独立会话、平衡顺序和分层
bootstrap 估计。

这五类不确定性不应压缩成一个普通“均值±标准差”。

## 4. 推荐的最低重复设计

### 4.1 数据划分

主结果使用一个预注册、冻结的 group-level 划分：

- train；
- valid；
- cal_op；
- cal_ch；
- test_op；
- test_ch。

稳健性实验另外使用 5 个 group-level 重划分或交叉拟合重复，但不能用这些结果选择
最有利的主划分。每次重划分都必须重新训练和重新校准。

推荐报告：

- 冻结主划分的正式结果；
- 5 个重划分的效应方向、均值、范围和风险越界次数；
- 不把同一查询出现在不同重划分中的结果当作独立样本。

### 4.2 训练seed

标准 AI+ 模型建议使用 5 个训练 seed：

\[
\mathcal S_{\mathrm{train}}
=
\{11,23,37,51,71\}.
\]

简单逻辑回归若使用确定性凸优化，可只训练一次，但仍需通过重划分或 bootstrap
评估数据不确定性。

每个训练 seed：

- 使用相同数据划分；
- 使用相同训练预算和早停规则；
- 按 valid 自动选择checkpoint；
- 不能根据 test 挑选最佳seed；
- 失败训练仍计入稳定性报告。

### 4.3 生成seed

随机解码时最低使用 3 个配对seed：

\[
\mathcal S_{\mathrm{gen}}
=
\{101,103,107\}.
\]

推荐敏感性实验增加至5个。所有配置和方法面对同一查询时使用相同seed集合。

如果 temperature=0 且后端经重复验证确定，可只使用1个固定seed，并以少量重复确认
非确定性；没有必要为了“重复次数”机械运行多个无效seed。

### 4.4 单查询设备测量

先导测量：

\[
30\text{ queries}
\times3\text{ configurations}
\times5\text{ repeats}.
\]

根据同条件变异系数决定正式重复：

| CV | 正式重复 |
| ---: | ---: |
| 不超过10% | 3次 |
| 10%–20% | 5次 |
| 超过20% | 8次，或先修正实验条件 |

重复运行采用配对和平衡顺序。不能让C0总在冷态、C2总在热态。

### 4.5 持续负载设备会话

每个策略×设备状态：

- 工程最低：3个会话；
- 论文最低：6个独立会话；
- 热退化是主要结论时：10个独立会话。

会话应跨重启、时间区组或实验批次。查询/配置顺序使用拉丁方或区组随机化。

若只有一块Radxa，结论只适用于该设备实例。要推广到设备型号，建议至少3块同型号
独立设备。

## 5. 推荐实验矩阵

### 5.1 安全与质量实验

对全部最终测试查询执行：

```text
每个查询
× C0/C1/C2
× 3个配对生成seed
```

C3单独评价回退是否恰当，不必复制完整生成配置的随机解码设计。

固定配置潜在结果矩阵完成后，可以重放不依赖实时热状态的路由策略。所有策略因此
使用完全相同的查询—配置输出，减少生成随机性造成的不公平。

### 5.2 静态资源实验

从测试集中按灾种、风险、配置难度和答案长度分层抽取至少300条查询，执行：

```text
300条查询
× 3个生成配置
× 冷态/预热/稳态
× 根据CV确定的3–5次重复
```

### 5.3 连续负载实验

对每个主要策略和设备状态执行6–10个独立会话。每会话使用相同查询池，但采用不同
预注册顺序；策略顺序跨会话平衡。

连续负载不能只通过固定潜在结果矩阵重放，因为策略选择会改变后续温度和设备状态。

## 6. 置信区间总原则

### 6.1 区间水平

- 双侧效果区间：95% CI；
- 校准安全声明：单侧95%风险上界；
- 探索性子组：95% CI，并明确未必有足够精度；
- 多个确认性比较：层级检验或Holm调整。

### 6.2 bootstrap次数

主结果建议：

\[
B=10{,}000
\]

次bootstrap。开发和调试阶段可用2,000次，正式表格使用10,000次并固定
`bootstrap_seed`。

### 6.3 组级重采样

每次bootstrap：

1. 在灾种层内重采样 `source_group_id`；
2. 抽中一个组时带入该组全部查询；
3. 带入每个查询的全部配置、生成seed和方法结果；
4. 重新计算方法差异；
5. 不重新调模型或测试阈值。

这样保持配对关系和同源查询相关性。

## 7. 二元安全结局

### 7.1 单方法L3风险

报告：

- L3次数；
- 分母；
- 点估计；
- Wilson或Clopper–Pearson 95% CI；
- 单侧95%上界。

样本很少或错误次数小于10时优先使用精确区间，不使用普通正态区间。

### 7.2 配对风险差

对PROPOSED与基线，定义：

\[
\Delta_{\mathrm{risk}}
=
\widehat P(Y_P=1)
-\widehat P(Y_B=1).
\]

报告：

- \(p_{10}\)：仅基线失败；
- \(p_{01}\)：仅PROPOSED失败；
- 配对绝对风险差；
- 组级配对bootstrap 95% CI；
- McNemar精确或中间P值；
- 必要时报告配对风险比。

禁止为两个方法分别计算独立比例区间后据此判断差异。

### 7.3 risk@coverage

每个方法同时报告：

\[
\operatorname{risk}
=
\frac{\text{被接受答案中的L3数}}
{\text{被接受答案数}},
\]

\[
\operatorname{coverage}
=
\frac{\text{被接受答案数}}
{\text{到达查询数}}.
\]

bootstrap时风险和coverage必须联合重算，不能固定分母。另报告：

- matched-coverage风险差；
- fixed-risk coverage差；
- C3率；
- 无安全配置率。

## 8. 校准阈值与安全上界

对每个配置报告：

- 校准集总数；
- 被阈值接受数；
- 接受coverage；
- 接受集合L3次数；
- 经验风险；
- 单侧Clopper–Pearson上界；
- \(\alpha,\delta_c\)；
- 最终阈值。

三个配置联合控制时使用：

\[
\delta_c=\delta/3.
\]

### 8.1 校准稳定性

建议对 `cal_op` 做2,000次group bootstrap：

1. 重采样校准查询组；
2. 重新选择每配置阈值；
3. 在固定valid或独立稳定性集合上计算coverage；
4. 报告阈值中位数、IQR、5%–95%范围；
5. 报告无可行阈值的比例。

这用于说明阈值敏感性，不能替代正式校准保证，也不能根据bootstrap结果选择最有利
阈值。

### 8.2 多次重划分

在5个group-level重划分中，报告：

- 达到目标风险的次数；
- 越界次数；
- coverage均值和范围；
- 无安全配置率；
- 阈值波动。

安全可信度不应只由某一次幸运校准划分证明。

## 9. 连续质量指标

### 9.1 行动完整率

同一查询的方法差：

\[
d_i
=
U_{i,P}-U_{i,B}.
\]

报告：

- 配对均值差和组级bootstrap 95% CI；
- 配对中位数差；
- 提高、相同和下降的查询比例；
- 灾种分层结果；
- matched-coverage结果。

恰当C3不应被简单记为行动完整率0。C3另行评价回退正确性。

### 9.2 引用与检索指标

Recall@k、引用支持率等比例指标使用查询组bootstrap。检索上限R2和事后oracle只报告
差距，不参与普通部署方法显著性排名。

## 10. 时延、能耗和内存

### 10.1 分布报告

资源指标通常偏态，至少报告：

- 均值；
- 中位数；
- P95；
- P99；
- IQR；
- 最大值；
- 完成率；
- 超时/OOM率。

不能只报告平均值。

### 10.2 配对效果

对能耗使用配对log比：

\[
d_i
=
\log E_{i,P}-\log E_{i,B}.
\]

bootstrap后转换为百分比：

\[
100[\exp(\bar d)-1]\%.
\]

报告节能百分比及95% CI。时延可使用同样方法，或报告配对毫秒差和比例差。

### 10.3 分层bootstrap

资源主结果使用两阶段bootstrap：

1. 重采样独立设备会话；
2. 在抽中的会话内按查询组重采样；
3. 保留配置和策略配对；
4. 重新计算均值、中位数、P95和策略差。

请求行级bootstrap会严重低估热态相关造成的不确定性。

### 10.4 P95/P99

P95/P99使用：

- 会话级bootstrap；
- 分位数回归；
- 或先计算每会话分位数，再对会话分位数报告中位数和范围。

只有3个会话时，不应给出看似精确的窄置信区间；应明确属于先导结果。

## 11. 训练seed结果

对5个训练seed分别报告：

- valid模型选择指标；
- test L3、coverage、行动完整率；
- 路由配置分布；
- 资源结果；
- 是否训练失败。

推荐呈现：

```text
查询抽样不确定性：冻结部署模型的group-bootstrap 95% CI
训练不确定性：5个seed的均值、标准差、最小值和最大值
```

不建议把5个seed×全部查询直接混在一起计算普通95% CI。只有5个seed时，seed层的
t区间会很不稳定，均值±SD和完整散点比单一窄区间更诚实。

如果必须给联合区间，可使用分层bootstrap：

1. 重采样训练seed；
2. 在seed内重采样查询组；
3. 重新计算平均方法差。

同时必须保留单seed结果，避免联合区间掩盖某些seed完全失效。

## 12. 数据缺失和系统失败

采用接近意向分析的原则：

- 超时记为时延约束失败；
- OOM记为资源不可行；
- 危险输出记为L3；
- 无恰当回退的空输出记为服务失败；
- C3计入coverage分母；
- 功率计日志损坏只使能耗缺失，不删除该查询的安全结果。

报告每种缺失原因和方法间缺失差异。不能只分析所有方法都成功的complete cases，
因为这会系统性删除复杂配置的失败。

对能耗缺失进行：

- complete-energy主描述；
- 将缺失视为最坏资源结果的敏感性分析；
- 不使用其他配置能耗简单均值插补。

## 13. 多重比较

建议一个确认性主比较，其95% CI不调整。其他比较按预注册层级：

1. PROPOSED vs 固定强配置；
2. PROPOSED vs 同架构未校准模型；
3. PROPOSED vs query-only模型；
4. PROPOSED vs二元安全路由；
5. 消融和子组。

探索性P值使用Holm–Bonferroni。置信区间同时报告未调整区间和多重比较说明，不应
只挑选显著结果。

## 14. 最小有意义差异

在查看正式测试结果前定义：

| 指标 | 建议初始阈值 |
| --- | ---: |
| L3绝对风险差 | 2个百分点 |
| 行动完整率差 | 5个百分点 |
| 能耗变化 | 10% |
| P95时延变化 | 10% |
| coverage变化 | 5个百分点 |

解释规则：

- CI完全超过最小有意义差异：支持具有实际意义的改善；
- CI排除伤害但未超过意义阈值：可能非劣但收益有限；
- CI同时跨越有益和有害阈值：结果不确定；
- CI较窄且落在等效范围：支持无实质差异；
- 不能把“P>0.05”解释为两方法相同。

## 16. 不允许的做法

- 重复运行直到P值显著；
- 查看测试结果后增加seed并只保留有利seed；
- 将同一查询的配置、生成seed和设备重复当作独立样本；
- 用普通行级bootstrap处理热态会话；
- 只报告均值±标准差而不报告配对效应；
- 只报告risk而隐藏coverage；
- 删除超时、OOM和C3；
- 根据测试结果修改校准阈值；
- 对小子组给出过度精确的结论；
- 把置信区间跨零解释为方法相同。

## 17. 推荐的最低可信方案

在无法严格计算样本量时，至少执行：

1. 一个冻结的group-level主划分；
2. 五个训练seed；
3. 随机解码时三个配对生成seed；
4. 每个静态资源条件三至五次重复；
5. 每策略×设备状态至少六个独立持续负载会话；
6. 五个group-level重划分稳健性实验；
7. 查询组级配对bootstrap 10,000次；
8. 设备会话—查询两阶段bootstrap；
9. L3精确区间和单侧风险上界；
10. 同时报告risk、coverage、效应量、CI、失败数和所有seed结果。

该方案不能弥补极小样本导致的宽区间，但能够真实展示证据精度，避免伪重复和选择性
报告，使“不确定”成为可见结论，而不是被大量运行行数掩盖。
