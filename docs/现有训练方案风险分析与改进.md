# 现有训练方案风险分析与改进

## 1. 审查范围

本审查区分两套方案：

1. **当前已经实现的训练器**：按 C0–C3 分别训练逻辑风险模型，使用 query-only
   特征和固定梯度迭代；
2. **计划实现的标准 AI+ 方案**：冻结文本编码器、查询/知识/设备特征融合、浅层
   共享主干和风险/效用/资源多任务输出。

两者不能混为一谈。当前代码结构简单，主要风险是数据与验证流程；计划中的 AI+
模型更复杂，主要风险是小样本过拟合、多任务梯度冲突和目标定义不一致。

## 2. 总体风险判断

| 风险 | 当前逻辑模型 | 计划 AI+ 模型 |
| --- | --- | --- |
| 参数过多 | 低 | 中高 |
| 数据伪重复 | 高 | 高 |
| 稀有正例过拟合 | 中 | 高 |
| 梯度爆炸/震荡 | 低至中 | 中高 |
| 多任务梯度冲突 | 无 | 高 |
| 概率失准 | 中 | 中高 |
| 目标定义不一致 | 中 | 高 |
| 标签/特征泄漏 | 中 | 中高 |
| 设备域偏移 | 未建模 | 高 |

当前训练查询约 1,440 条，L3 正例可能只占 1%–10%。在这一规模下，最需要避免的
不是“模型不够深”，而是用复杂结构拟合标签噪声、查询模板和设备会话伪迹。

## 3. 可能导致过拟合的原因

### 3.1 独立样本数量被高估

同一查询对应 C0–C2、多个生成 seed 和多个设备重复。若将这些记录逐行输入模型：

\[
N_{\mathrm{apparent}}
=
N_q\times K\times S\times R,
\]

但真实独立语义单位仍接近 \(N_q\)。重复记录会使模型过度记忆查询、模板或设备会话，
并产生过窄的验证区间。

当前 `train-risk` 会读取所有成功运行行；若实验有多个 repetition，同一
query–configuration 会被重复训练，形成伪增样本。

#### 改进

- 先按 `query_id + configuration` 聚合；
- L3 使用预注册的“任一 seed 失败”或“seed 平均风险”标签；
- 资源使用会话内中位数和 P95，而非把重复测量当作独立训练样本；
- batch、数据划分和 bootstrap 以 `source_group_id` 为组；
- 保存 `n_queries`、`n_query_config_pairs` 和 `n_runs` 三个不同统计量。

### 3.2 样本小而模型自由度过多

计划 AI+ 模型同时包含：

- 文本投影；
- 五组特征编码；
- 两个配置门控；
- 特征组注意力；
- 两层残差主干；
- 风险、效用、时延、能耗、内存和回退多个输出头。

在 1,440 条训练查询上全部同时训练，容易出现验证指标波动、注意力记忆灾种模板和
辅助头支配共享表示。

#### 改进

采用逐级增加复杂度：

1. TF-IDF/BM25 + 逻辑回归；
2. 冻结文本编码器 + 逻辑风险头；
3. 加知识和设备结构化特征；
4. 只有验证误差分析支持时才加入门控；
5. 注意力必须通过消融证明收益，否则删除；
6. 辅助任务逐个加入，不一次性开启全部损失。

建议首个 AI+ 版本不使用注意力，只用拼接和一层门控。

### 3.3 稀有正例被模型记忆

L3 样本少且可能集中在少数灾种、模板或协议。高正类权重、正例过采样和复杂文本
编码器结合后，模型可能记住表面词，而非学习可迁移风险。

#### 改进

- 每灾种、语言和 query type 报告正例数；
- 使用 group-stratified batch；
- 正类权重采用平方根比例并限制上限；
- 不同时使用高权重、强过采样和 focal loss；
- 使用 PR-AUC、L3 recall、Brier 和最坏子组风险，而非准确率选择模型；
- 通过跨事件和同义改写挑战集检查词汇捷径。

### 3.4 标签噪声和模板伪迹

专家对严重失效、必要行动和恰当回退可能有分歧；机器生成查询还可能带有明显模板
风格。模型可能学习“由哪个模板生成”，而不是应急风险。

#### 改进

- 至少双人盲法标注，高风险冲突由第三人裁决；
- 保存分歧比例和标注者 ID；
- 同一模板、协议条款和事件必须在同一 `source_group_id`；
- 主训练使用裁决标签，软标签仅做敏感性分析；
- 不删除所有分歧样本，而应报告高分歧子组；
- 检查模型能否根据 query generator/source 预测标签；若可以，说明存在模板捷径。

### 3.5 特征泄漏

可能泄漏的特征包括：

- 人工标注后的 `gold_should_fallback`；
- gold evidence 数量或召回；
- 测试配置的真实时延、能耗和错误结果；
- 根据完整 C2 输出计算的冲突分数；
- 人工 risk level 若其实由 L3 结果倒推；
- 测试后修订的关键词和协议规则。

#### 改进

- 建立决策时可观测特征白名单；
- 每个特征记录采集时点和依赖数据；
- 只允许低成本预检索状态进入路由器；
- gold 特征只进入评价器和 oracle；
- 用自动测试检查训练矩阵是否含 `gold_*`、答案评分或未来结果列。

### 3.6 过多超参数选择

多任务权重、门控、注意力、隐藏维度、dropout、正类权重和学习率共同形成很大的
搜索空间。即使从不查看测试集，也可能对仅 360 条 valid 过拟合。

#### 改进

- 预注册不超过 20–30 个总 trial；
- 使用由简到繁的顺序搜索，不做所有组合笛卡尔积；
- 采用一个标准误规则选择更简单模型；
- 多任务权重只做小范围离散搜索；
- calibration 不用于架构和损失权重选择；
- 报告所有失败 trial 和总调参预算。

## 4. 可能导致梯度不稳定的原因

### 4.1 类别权重与过采样叠加

若 L3 正例同时被重复采样并赋予高权重，单个正例可能贡献几十倍梯度，导致风险头
震荡、概率趋近 0/1 和共享主干被稀有样本支配。

#### 改进

三种方法只选一种为主：

1. group-stratified batch；
2. 有限正类权重；
3. focal loss 消融。

推荐“分层 batch + 上限 3 的正类权重”。梯度全局范数裁剪：

\[
\|\nabla_\theta\mathcal L\|_2\leq1.0.
\]

### 4.2 多损失尺度不同

BCE 通常为 \(10^{-1}\) 量级，原始毫秒 MSE、焦耳误差和内存误差可能大数个数量级。
若不变换，资源头会压制主风险头。

#### 改进

- 时延、能耗和内存先使用 `log1p` 或 log 变换；
- 各辅助损失按训练集初始尺度归一化；
- 每个 batch 记录各任务原始 loss 和加权 loss；
- 主风险梯度占比过低时降低辅助权重，而非继续增大网络；
- 能耗缺失时用 mask 跳过，不能填 0。

对于可能为 0 的资源值，使用：

\[
\log(1+y)
\]

而不是直接 \(\log y\)，避免 \(-\infty\) 和 NaN。

### 4.3 Pinball loss 不光滑

分位数 pinball loss 在残差为 0 处不可微，叠加噪声设备测量时可能使小 batch 梯度
抖动。

#### 损失替换

使用 Huberized quantile loss：

\[
\mathcal L_{\tau,\kappa}(e)
=
\begin{cases}
\tau H_\kappa(e), & e\geq0,\\
(1-\tau)H_\kappa(e), & e<0,
\end{cases}
\]

其中 \(H_\kappa\) 为 Huber 核。建议在标准化空间搜索：

\[
\kappa\in\{0.05,0.10,0.25\}.
\]

### 4.4 门控饱和与注意力塌缩

sigmoid gate 可能过早接近 0 或 1，softmax 注意力可能只依赖一个特征组，使其他
模态得不到梯度。

#### 改进

- gate bias 初始化为 0，使初始值约为 0.5；
- 保留原始特征旁路，不让 gate 完全删除输入；
- 监控 gate 饱和比例；
- 注意力初始版本可不启用；
- 若启用，监控注意力 entropy，不将权重解释为因果；
- 不建议为了防塌缩加入大权重 entropy loss，优先简化结构。

### 4.5 学习率过高

当前逻辑模型使用全批量、初始学习率 0.1 和固定 1,200 次迭代；对标准化简单逻辑
回归通常可运行，但没有 valid 早停。对于计划 AI+ 网络，直接沿用该学习率会导致
明显震荡。

#### 改进

- 逻辑回归优先使用稳定凸优化求解器；
- 浅层 AI+ 头使用 AdamW，学习率从 \(3\times10^{-4}\) 至 \(10^{-3}\)；
- 部分微调编码器时使用 \(10^{-6}\) 至 \(2\times10^{-5}\)；
- 5% warmup 后 cosine decay；
- 出现梯度尖峰时先降低学习率和正类权重，不先增加 warmup 或网络深度。

### 4.6 多任务梯度冲突

风险、完整率和能耗的理想方向可能不同。例如 C2 可能提高完整率但增加能耗；若共享
主干同时最小化这些损失，梯度可能互相抵消。

#### 改进

优先采用两阶段或分离模型：

1. 单独训练风险/效用模型；
2. 单独训练设备资源模型；
3. 在决策层通过硬约束组合。

如果必须共享主干：

- 先训练风险头，再逐个加入辅助头；
- 记录任务梯度余弦相似度；
- 仅当持续观察到负梯度相似度时，才把 PCGrad/GradNorm 作为辅助实验；
- 不默认使用自动任务权重，因为它可能降低主风险权重；
- 可对资源头使用 stop-gradient 或更浅的独立分支。

## 5. 可能导致目标不一致的原因

### 5.1 训练概率与部署安全目标不同

加权 BCE、过采样和 focal loss优化的是训练分布分类，部署目标是接受集合中的 L3
风险不超过 \(\alpha\)。分类准确率提高不保证 risk@coverage 改善。

#### 改进

- 主损失保持 BCE/Brier；
- 每个模型单独在相同 `cal_op` 上校准；
- 同时比较 NLL/Brier、risk@coverage 和实际 coverage；
- 不以 F1 或 AUROC 单独选择安全模型。

### 5.2 “任一 seed 失败”与“平均 seed 风险”混用

最坏 seed 标签更保守，平均 seed 标签反映随机解码风险。二者对应不同安全问题，
若训练使用平均标签、校准使用最坏标签，模型目标会不一致。

#### 改进

主实验统一使用一个预注册定义。另一个定义只作敏感性分析，并从训练到评价全流程
一致。

### 5.3 风险、完整率和回退的逻辑不一致

一个答案可能行动完整但包含严重危险建议；C3 虽无行动完整率，却可能是正确安全
决策。若把这些目标简单加总，会错误惩罚恰当回退或奖励完整但危险的回答。

#### 改进

采用字典序决策：

1. 首先排除不满足 L3 风险约束的配置；
2. 再排除资源不可行配置；
3. 再要求最低效用；
4. 最后最小化能耗；
5. C3 单独评价“回退是否恰当”，不与生成答案使用同一完整率分母。

训练损失可以多任务，但在线决策不能用简单加权和替代安全硬约束。

### 5.4 资源目标与测量域不一致

若资源模型用 Windows 冷态数据训练，却在 Radxa 热态部署，或能耗标签只覆盖部分
电源轨，模型会优化错误目标。

#### 改进

- 资源模型只使用目标 Radxa 的实测数据；
- 冷态、预热和稳态分层；
- 设备型号、内核、功耗模式、散热和模型版本进入数据清单；
- 使用 P95/越界概率而非只预测平均值；
- 更换设备或模型量化后重新训练/画像。

### 5.5 回退辅助头与硬回退规则冲突

回退头可能预测“不回退”，但所有 C0–C2 都未通过校准安全门。若软头覆盖硬规则，
会破坏方法定义。

#### 改进

硬规则优先级固定为：

```text
传感器/模型硬故障
→ 校准安全集合
→ 资源可行集合
→ 最低效用
→ 回退辅助头
→ 资源排序
```

无安全配置时始终 C3。

## 6. 损失函数替换建议

| 当前/候选损失 | 主要风险 | 推荐替换或处理 |
| --- | --- | --- |
| 高权重 BCE | 梯度尖峰、概率偏移 | 普通 BCE + 小 Brier；正类权重限制 3–5 |
| Focal loss | 排序改善但概率变差 | 仅作消融，每个版本独立校准 |
| 原始尺度 MSE | 资源任务压制风险任务 | `log1p` + Huber |
| 标准 pinball | 噪声下梯度抖动 | Huberized quantile loss |
| 多任务自动权重 | 可能降低主风险权重 | 预注册固定小权重，逐任务加入 |
| 大权重 ranking loss | 与概率估计冲突 | 默认关闭或权重不超过 0.05 |
| 标签平滑 | 模糊安全正例 | 主实验不使用；保留标注分歧信息 |
| 所有任务共享深主干 | 负迁移 | 风险与资源分离，或浅共享+独立头 |

推荐最稳健起点：

\[
\mathcal L
=
\mathcal L_{\mathrm{BCE}}
+0.1\text{--}0.25\mathcal L_{\mathrm{Brier}}
+0.05\text{--}0.20\mathcal L_{\mathrm{utility}}
+0.05\text{--}0.10\mathcal L_{\mathrm{resource}}.
\]

## 7. 采样策略

### 7.1 推荐 batch 构造

1. 以 `source_group_id` 抽取独立查询组；
2. batch 内按灾种、语言和 L3 分层；
3. 对抽中的查询同时放入 C0–C2；
4. 多 seed 先聚合为主标签，或使每个 seed 权重为 \(1/S\)；
5. 多设备 repetition 的风险总权重不增加；
6. 资源头可保留重复运行，但用 session ID 做 block 权重。

### 7.2 正例过采样范围

若 batch 中正例过少，可将含 L3 查询组的抽样概率提高：

\[
\text{oversampling factor}\in\{1,1.5,2,3\}.
\]

不建议超过 3。若使用 2–3 倍过采样，正类损失权重应接近 1；不要叠加上限 5 的
类别权重。

### 7.3 困难样本

训练后可从 train 中识别高置信错误样本，每 epoch 困难样本比例限制为：

\[
10\%\text{--}25\%.
\]

困难样本挖掘不能访问 valid/calibration/test，也不能长期只训练少数争议标签。

### 7.4 不推荐策略

- query 行级随机划分；
- SMOTE 文本 embedding；
- 把设备重复当作新查询；
- 按测试错误补采样训练；
- 删除所有 C3 或所有困难正例；
- 只报告重平衡后的评价结果。

## 8. 数据增强策略

### 8.1 查询文本增强

候选增强：

- 同义改写；
- 口语/书面语转换；
- 轻微错别字、空格和标点扰动；
- 等义语序变化；
- 中英文术语别名。

增强强度建议：

| 参数 | 范围 |
| --- | --- |
| 被增强训练查询比例 | 10%–30% |
| 单条查询增强版本 | 1–2 |
| 字符扰动率 | 1%–3% |
| 同义替换比例 | 不超过内容词的 10% |

所有增强继承原 `source_group_id`。关键限制是：即使语义基本不变，改写也可能改变
检索结果和生成输出。因此正式风险标签应重新运行 C0–C2 并复核，不能直接复制原
query–configuration 结果。

### 8.2 信息删除增强

删除地点、对象、时间或条件可用于训练信息不足和 C3，但它会改变任务标签。必须：

- 创建新的 query ID；
- 与原查询保持同一 source group；
- 重新标注 `should_fallback`、必要动作和 L3；
- 不能把原答案标签直接继承。

### 8.3 知识状态增强

可模拟：

- 检索服务不可用；
- top score 小幅噪声；
- 协议冲突标志；
- 元数据缺失。

其中传感器或分数噪声应依据实际误差：

\[
\epsilon\sim\mathcal N(0,\gamma^2\sigma_{\mathrm{meas}}^2),
\quad
\gamma\in\{0.25,0.5,1.0\}.
\]

改变协议版本、证据内容或冲突关系会改变真实安全标签，不能仅作数值增强。

### 8.4 设备状态增强

- 随机屏蔽单个遥测变量：5%–10%；
- 整组设备特征 dropout：0%–10%；
- 按实测传感器误差加入 0.25–1.0 倍标准差噪声；
- 温度、功率、负载组合必须保持物理可行；
- 不使用任意 mixup 生成不存在的设备状态。

### 8.5 增强是否保留的标准

仅当增强带来：

- 原始 valid 不退化；
- 挑战 valid 稳定改善；
- Brier/NLL 不恶化；
- 多 seed 方向一致；
- Radxa 路由翻转更合理；

才进入主训练方案。

## 9. 推荐超参数范围

### 9.1 模型结构

| 超参数 | 推荐范围 |
| --- | --- |
| 文本投影维度 | 32、64 |
| 查询/知识/设备投影维度 | 16、32 |
| 配置 embedding | 8、16 |
| 共享隐藏维度 | 64、128 |
| 隐藏层数 | 1、2 |
| 门控 | 关闭、单层门控 |
| 特征组注意力 | 默认关闭；仅作开/关比较 |

当前数据规模不建议隐藏维度超过 128 或主干超过 2 层。

### 9.2 优化

| 超参数 | 推荐范围 |
| --- | --- |
| 浅层头学习率 | \(3\times10^{-4}, 5\times10^{-4}, 10^{-3}\) |
| 编码器学习率 | 冻结；辅助微调时 \(10^{-6}\)–\(2\times10^{-5}\) |
| weight decay | \(10^{-5},10^{-4},10^{-3}\) |
| query-group batch | 8、16、32 |
| warmup 比例 | 3%、5%、10% |
| 梯度裁剪 | 0.5、1.0、2.0 |
| 最大 epoch | 50–150 |
| early-stop patience | 8–15 |
| 最小相对改善 | \(10^{-3}\) |

### 9.3 不平衡与正则化

| 超参数 | 推荐范围 |
| --- | --- |
| 正类权重上限 | 1、3、5 |
| 正例组过采样倍数 | 1、1.5、2、3 |
| 普通 dropout | 0.05、0.10、0.20 |
| 特征组 dropout | 0、0.05、0.10 |
| Brier 权重 | 0.10、0.25、0.50 |
| utility 权重 | 0.05、0.10、0.20 |
| 单项 resource 权重 | 0.02、0.05、0.10 |
| ranking 权重 | 0、0.02、0.05 |
| Huberized quantile \(\kappa\) | 0.05、0.10、0.25 |
| 资源分位数 | 0.50、0.90、0.95 |

不应对所有范围做完全网格。建议先锁定简单架构，在不超过 20–30 个 trial 内顺序
选择学习率/正则、类别处理、辅助权重和可选门控。

## 10. 诊断与停止条件

### 10.1 过拟合诊断

- train NLL 持续下降但 valid NLL/Brier 上升；
- valid 不同 seed 方差超过平均改进；
- query template/source 可以高准确率预测模型错误；
- 注意力长期集中在单一特征组；
- 训练集 PR-AUC 很高但挑战集接近机会水平；
- 简单逻辑回归与复杂模型差异位于一个标准误以内。

出现上述情况时应减少隐藏维度、删除注意力/辅助头、提高正则或增加组级数据，而不是
继续训练更久。

### 10.2 梯度诊断

每 epoch 记录：

- 总梯度范数；
- 各任务加权前后 loss；
- 风险头与资源头梯度余弦；
- gate 饱和比例；
- 注意力 entropy；
- NaN/Inf batch；
- 最大单 batch 正例权重。

若连续三个 epoch：

- 梯度裁剪触发超过 20% batch；
- 任一辅助任务梯度范数超过风险任务 5 倍；
- gate 超过 90% 值落在 \([0,0.05]\cup[0.95,1]\)；

则暂停训练并降低学习率/任务权重或简化融合模块。

### 10.3 目标一致性诊断

模型只有同时满足下列条件才进入 `cal_op`：

- valid NLL/Brier 不劣于简单基线；
- L3 recall 和最坏子组风险达到预注册标准；
- auxiliary loss 改善没有降低主风险指标；
- 资源预测在冷态和热态均通过误差检查；
- C3 回退率没有通过极端保守策略异常升高；
- 路由开销预计不会抵消配置节省。

## 11. 建议的改进版训练顺序

```text
阶段 0：聚合 query–configuration 标签，完成泄漏和组划分检查

阶段 1：训练无类别权重的逻辑回归/BCE 基线

阶段 2：加入 Brier 和有限不平衡处理
         只保留 valid 上稳定改善的版本

阶段 3：加入冻结文本编码器
         不使用注意力、不使用多任务

阶段 4：加入知识和设备特征
         检查 –Corpus / –Device 消融

阶段 5：单独训练资源模型
         使用 log1p + Huberized quantile

阶段 6：仅在证实正迁移后共享浅层主干
         逐个加入 utility/resource/fallback 辅助头

阶段 7：门控与注意力只作为最后的开/关消融

阶段 8：模型完全冻结后进入独立安全校准
```

## 12. 最终建议

最优先修正的四项是：

1. 当前训练前按 query–configuration 聚合重复 runs，消除伪增样本；
2. 为当前逻辑训练器加入 valid 早停或使用稳定凸优化器；
3. AI+ 初版分离风险模型和资源模型，避免多任务梯度冲突；
4. 使用 BCE + 小权重 Brier、有限正类权重和 Huberized quantile，而不是一开始
   同时启用 focal、排序、多任务自动加权和注意力。

若复杂模型相对简单逻辑回归的改善小于 seed 方差或一个标准误，应保留简单模型，
而不是通过扩大搜索空间寻找偶然优势。
