# 离线应急 RAG 标注一致性评估方案 v1.0

**适用范围：**查询级风险/回退/证据/行动标注，以及配置输出级安全审查  
**数据位置：**`D:\projects\RAG-sci\docs\sci-exp\data\annotations`、`data\logs`  
**评估目标：**判断标注是否足够稳定，可用于训练、校准、验证和最终测试

## 1. 先区分三个对象

一致性评估必须使用同一条记录的**独立 A/B 原始标注**，不能用仲裁结果与某一名标注员比较，也不能用模型预测和人工标签比较。

| 对象 | 一致性问题 | 主要用途 |
|---|---|---|
| 查询风险等级 `L0–L3` | 有序类别是否一致 | 评估风险标签是否可学习 |
| 回退 `should_fallback` | 二元类别是否一致 | 评估安全边界是否稳定 |
| 证据/行动集合 | 集合重叠和覆盖是否一致 | 评估 gold 是否能支撑监督信号 |
| 输出审查分数 | 连续或等级评分是否一致 | 评估安全结局标签和模型比较可靠性 |

仲裁后的标签是最终 gold，但不应被当作“独立一致性”证据。若只有仲裁结果而没有 A/B 原始文件，该批次只能标记为“已仲裁”，不能报告标注者一致性。

## 2. 指标选择总表

| 标签类型 | 首选指标 | 补充指标 | 不建议单独使用 |
|---|---|---|---|
| `risk_level` L0–L3 | 加权 Cohen’s Kappa（建议 quadratic） | 原始一致率、4×4 混淆矩阵、分层 Kappa | 普通准确率 |
| L3/非 L3 | 二元 Cohen’s Kappa | 灵敏度、特异度、阳性一致率 | 只看 L3 比例 |
| `should_fallback` | 二元 Cohen’s Kappa | 阳性/阴性一致率、混淆矩阵 | 只看准确率 |
| evidence ID 集合 | Dice、Jaccard/IoU | 精确集合一致率、集合级 Precision/Recall | 把空集合当作普通字符串比较 |
| required/prohibited actions | 动作 ID 级 Dice/IoU、Micro/Macro F1 | 完全匹配率、动作混淆表 | 只比较整串文本 |
| `action_completeness` 0–1 | ICC（双向、绝对一致、single-rater） | 加权 Kappa、Bland–Altman 或 MAE | 二元 Kappa |
| 有序输出等级 | 加权 Kappa | ICC（等级数量足够且可视为近似连续时） | 未加权 Kappa |
| 文本严重失效/危险动作 | 二元 Kappa | 阳性一致率、严重错误漏标率 | 用 Dice 代替二元标签一致性 |

### 2.1 为什么要使用加权 Kappa

`L0` 与 `L1` 的分歧通常小于 `L0` 与 `L3` 的分歧。加权 Kappa 可对远距离分歧赋予更大惩罚。正式报告必须同时给出：

```text
加权 Kappa + 原始一致率 + 4×4 分歧矩阵 + 95% 置信区间
```

### 2.2 为什么不把 ICC 用在所有字段

ICC 衡量连续或近似连续评分的绝对一致性，不适合直接用于 `risk_level`、`should_fallback` 或 evidence ID。`action_completeness` 是 0–1 比例，可使用双向随机效应、绝对一致、单次测量的 ICC；若评分只有少数离散等级，应以加权 Kappa 为主。

### 2.3 Dice 与 IoU 的关系

对两个集合 \(A\) 和 \(B\)：

\[
\mathrm{Dice}(A,B)=\frac{2|A\cap B|}{|A|+|B|}
\]

\[
\mathrm{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}
\]

两者关系为：

\[
\mathrm{Dice}=\frac{2\mathrm{IoU}}{1+\mathrm{IoU}}
\]

本项目建议以 IoU/Jaccard 作为 evidence 集合主指标，以 Dice 作为易解释的补充指标。两个集合均为空时记为 1；只有一边为空时记为 0，并单独报告空集合比例，防止证据缺失造成虚高。

## 4. 具体计算方案

### 4.1 风险等级

对每一批次分别计算：

1. quadratic weighted Cohen’s Kappa；
2. exact agreement；
3. 相邻分歧率 \(|A-B|=1\)；
4. 严重分歧率 \(|A-B|\ge 2\)；
5. L3 二元化 Kappa；
6. 按 `query_type`、`disaster_type`、`source_group_id` 和数据分区分层。

不得把同一 `source_group_id` 的多条记录当作完全独立样本来计算置信区间。置信区间建议按 source group 聚类 bootstrap。

### 4.2 回退标签

计算二元 Cohen’s Kappa，并同时报告：

- A/B 原始一致率；
- `true/true`、`true/false`、`false/true`、`false/false` 四格表；
- 回退阳性一致率；
- 以“保守回退”作为阳性类别的漏标数；
- L2/L3 子集与证据缺口子集的一致性。

安全研究中，`should_fallback=true` 被漏标通常比多回退更危险。因此报告中要单独列出 `A=false,B=true` 和 `A=true,B=false`，不能只给一个 Kappa。

### 4.3 证据集合

先把每个 evidence ID 规范化为集合，去除重复、空格和顺序差异，再计算：

- exact set match；
- mean/median IoU；
- mean/median Dice；
- evidence-level Precision、Recall、F1；
- 空集合双方一致、单边空集合和双方非空比例；
- 按协议家族、灾种、查询类型和机器候选是否命中分层。

证据集合的顺序不影响一致性。`EVIDENCE_001|EVIDENCE_002` 与反向顺序视为相同集合。

### 4.4 行动集合

必须先建立稳定的动作字典，将同义表述映射到动作 ID；不得直接按中文字符串比较。例如“立即拨打 120”和“马上呼叫急救”可映射到同一动作 ID，但“联系救援”不能自动等同于“拨打 120”。

对 `required_actions` 和 `prohibited_actions` 分别计算：

- action-level Micro F1；
- action-level Macro F1；
- Dice/IoU；
- exact match；
- required/prohibited 交集冲突数。

任何 required/prohibited 交集都属于质量阻断项，即使总体 Dice 很高也不能通过。

### 4.5 输出级连续评分

对每个 `query_id + configuration + repetition`：

- `action_completeness`：使用 ICC(2,1)，即双向随机效应、绝对一致、单次测量；
- 同时报告 95% CI、MAE 和 Bland–Altman 偏差；
- 若评分被离散成 0、0.5、1 等少数等级，以 quadratic weighted Kappa 为主，ICC 为补充；
- `severe_failure`、`evidence_correct`、`fallback_correct`、`prohibited_action_violation` 使用二元 Kappa。

输出级评分必须在配置和重复层面保持配对；不能把 C0 的 A 标注与 C3 的 B 标注配成一对。

## 5. 推荐判定阈值

阈值用于决定数据能否进入不同阶段，不是对研究结论的替代。

| 水平 | Kappa/ICC | Dice/IoU | 数据处理 |
|---|---:|---:|---|
| 优秀 | ≥0.80 | ≥0.80 | 可进入正式训练/校准；保留仲裁和抽检 |
| 可接受 | 0.67–0.79 | 0.67–0.79 | 可用于开发训练；核心高风险子集需复核 |
| 边界 | 0.50–0.66 | 0.50–0.66 | 不直接用于最终校准；先修订手册并复标 |
| 不合格 | <0.50 | <0.50 | 暂停该标签训练，检查定义、证据和人员培训 |

硬性安全门槛：

- L3/非 L3 Kappa < 0.80：不得用于安全约束校准；
- `should_fallback` Kappa < 0.80：不得用于回退策略训练；
- 任一 evidence/action 子集 IoU < 0.67：该子集必须复核；
- 出现任何未仲裁的危险动作或 required/prohibited 冲突：批次不冻结；
- 置信区间下限低于门槛时，按下一级处理，而不是按点估计通过。

若某字段类别极不平衡，Kappa 可能受 prevalence 影响。此时必须补充阳性一致率、分层混淆矩阵和原始一致率，不能用高准确率掩盖少数类漏标。

## 6. 不同一致性水平对模型训练的影响

### 6.1 优秀一致性

可以：

- 将仲裁后的标签用于监督训练或校准训练；
- 使用证据和行动标签构造辅助损失；
- 进入配置选择器的风险约束目标；
- 在论文中报告独立双审的一致性证据。

仍需保留高风险抽检，因为高一致性可能来自模板重复或标签捷径。

### 6.2 可接受一致性

可以用于开发集或预训练式任务，但建议：

- 对分歧样本提高仲裁权重；
- 不把细粒度 evidence/action 标签作为硬目标，可使用软标签或集合损失；
- 单独报告 L3、C3、域外和证据缺口子集；
- 暂不把该批次作为最终测试 gold。

### 6.3 边界一致性

不应直接训练安全决策器。否则模型会学到标注噪声，表现为：

- 风险概率被过度平滑或过度自信；
- 回退阈值对随机标注变化敏感；
- 证据检索器学习到错误协议；
- 训练/验证指标不稳定，重复实验置信区间变宽。

处理顺序应为：定位分歧类型 → 修订标签定义或证据版本 → 对分歧项重新双审 → 再计算一致性。

### 6.4 不合格一致性

该标签不得进入正式训练、校准或测试。可以保留为错误分析材料，但必须标记为 `annotation_status=needs_reannotation`，不能通过多数投票伪造稳定 gold。

## 7. 置信区间、重复与报告格式

每个主指标报告：

```text
指标名称 = 点估计，95% CI，样本数 n，分层范围，计算版本
```

建议：

- Kappa：按 source group 聚类 bootstrap 2,000 次；
- Dice/IoU：按 source group 聚类 bootstrap 2,000 次；
- ICC：报告 ICC 类型、模型、单次/平均测量；
- 置信区间若跨越两个决策档位，按较低档位处理；
- 主报告给总体值，补充材料给每个灾种、查询类型、风险等级和配置值。

建议保存：

```text
data/logs/标注一致性评估报告_v1.0.json
data/logs/标注一致性分层明细_v1.0.csv
```

报告至少包含原始 A/B 文件 SHA-256、规范版本、动作字典版本、证据库版本、统计脚本版本和生成时间。

## 8. 训练前决策门

### 允许进入训练

- 风险 Kappa 及其 CI 下限达到 0.67，且 L3 二元 Kappa 达到 0.80；
- 回退 Kappa 及其 CI 下限达到 0.80；
- evidence/action 集合 IoU 至少达到 0.67；
- 无未仲裁危险动作；
- 数据状态为 `adjudicated`，开发集/校准集/测试集角色明确。

### 只允许开发使用

- 总体指标达标，但某个高风险或证据缺口子集低于门槛；
- 只能使用软标签、样本降权或仅用于错误分析；
- 不能用于最终阈值选择和确认性结论。

### 必须返工

- L3、回退或危险行动一致性低于安全门槛；
- evidence/action IoU 低于 0.50；
- 现有 A/B 文件缺失，只有仲裁结果；
- 发现通过模板后缀、灾种元标签或机器候选泄漏标签。
