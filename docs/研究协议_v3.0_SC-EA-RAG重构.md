# 研究协议 v3.0：SC-EA-RAG输入-配置风险与真实能耗实验

状态：依据《SC-EA-RAG 中文重构研究稿》更新的实施协议。它替代v2.0作为后续
代码、标注和硬件实验的当前口径；v2.0保留作变更审计，不删除、不覆盖。

## 1. 研究对象和决策单位

基本样本不是单个输入，而是`(输入x, 设备状态d, 固定配置c)`。每个固定配置必须
真实运行并保留回答、检索证据、时延、内存、设备温度、环境条件和物理能耗。

设备状态至少包含：

- 可用能源预算或电量等级；
- Radxa SoC设备温度；
- 可用内存。

SHT31环境温度和湿度是实验控制与复现字段，不得替代SoC设备温度，也不默认作为
路由输入。若后续把环境变量纳入模型，必须在查看Gold Test前修订协议。

## 2. 冻结配置库

当前工程配置映射如下：

| ID | 论文角色 | 检索与生成属性 |
|---|---|---|
| C0 | Fixed-Light | 无检索，保守直接生成，输出上限128 token |
| C1 | Fixed-Medium | 单步BM25+BGE混合检索，Top-5，上下文约3000字符，输出上限256 token |
| C2 | Fixed-Full | 协议过滤、多步混合检索与重排，Top-8，上下文约6000字符，输出上限512 token |
| C3 | Fallback | 确定性安全回退，不调用生成模型 |

正式Profiling完成后才能冻结最终配置库。若改动模型、检索器、Top-k、重排、上下文
上限、输出上限或生成模式，必须重新画像、标注受影响输出并重新校准。

## 3. 三层标签

### 输入级协议Gold

必须记录`risk_state`的Positive/Negative/Unknown三状态、严重度、必要动作集合、
禁止动作集合、升级需求、操作/设备约束和原文证据跨度。Unknown不得映射为Negative。

### 输出级动作标签

每个输入-配置回答至少双人盲审以下字段：

- `trigger_negated`；
- `trigger_forbidden`；
- `dangerous_action`；
- `missing_action_vector`；
- `protocol_correct`；
- `evidence_relevant`；
- `constraint_preserved`；
- `actionable`；
- `error_severity`（0--4）。

### 输入-配置级合成标签

```text
y_trigger = trigger_negated OR trigger_forbidden OR dangerous_action
y_miss = any(missing_action_vector)
y_quality = protocol_correct AND evidence_relevant AND
            constraint_preserved AND actionable AND NOT dangerous_action
```

旧的`severe_failure`仅作为兼容/补充结局，不能替代三个主要标签。

## 4. 数据隔离

配置搜索只使用Profiling Split。模型选择、温度缩放、阈值校准和最终测试必须分别
使用独立角色的数据。当前400条仍是development gold，不得因已有文件名为
`cal_*`或`test_*`就冒充正式Gold Calibration或Gold Test。

正式分区和样本量必须在完成新的功效分析、来源配额和专家标注能力评估后冻结。
不得直接沿用v2.0的3600条设计，也不得根据最终测试结果反向修改样本量。

## 5. 硬约束路由

风险模型必须分别预测误触发、必要动作遗漏和最低充分性失败。阈值只在独立Gold
Calibration上确定。部署时先构造同时满足三个风险阈值的配置集合，再施加时延、
内存和能源预算，最后选择预测净能耗最低的配置；集合为空时执行C3。

风险、质量与能耗不得压缩成可以相互补偿的单一加权分数。Energy-Only和Soft
Weighting只能作为对照。

## 6. 真实硬件测量

- 主平台：Radxa ZERO 3W；
- 功率：ESP32-S3 + INA226 + R010，高边测量Radxa 5V输入；
- 功率采样：不低于100Hz；
- 环境：SHT31，约1Hz；
- 设备温度：Radxa thermal zone，约5Hz；
- CPU频率/热降频：cpufreq与thermal cooling state，约5Hz；
- 每个输入-配置运行顺序随机化并记录`run_order`；
- 能耗采用相对空闲功率积分；空闲窗口、预热、缓存、线程数和散热条件须冻结；
- 共享编码、配置评分、检索、重排、提示构造和生成全部计入端到端边界。

外部功率日志必须通过`run_key`与运行日志合并。没有有效起止标记、少于两个功率点、
采样间隔超过30ms、欠压、饱和或积分断点的运行不得进入能耗主分析。

## 7. 对照和主报告

至少报告Fixed-Light、Fixed-Medium、Fixed-Full、Fallback、Energy-Only、完整搜索后的
Soft Weighting、SC-EA-RAG、Oracle Safety Mask和Full Oracle。其他复杂度/置信度/
LLM路由基线在实现且公平计入路由开销后报告。

主要能耗结论只能在匹配危险配置放行率或高风险动作召回时比较。必须报告UAR、SER、
Set-F1、Jaccard、Exact Set Match、空可行集合率、净能耗、P95时延、峰值内存、
设备温度和95%置信区间，并单列Hard、高危、否定和操作约束子集。

## 8. 当前门禁

截至2026-08-11，代码接口已支持Chat API、多头风险、100Hz INA226、SHT31环境记录、
SoC温度/频率/冷却状态和外部能耗合并。以下事项仍未完成，不能形成投稿结果：

- SHT31和INA226实物I2C验收；
- INA226三点校准及60分钟稳定性；
- UART4在Radxa上的设备树启用与双向验收；
- 正式配置Profiling和冻结；
- 新三层Gold标签的专家双审；
- 多头模型训练、温度缩放和独立阈值校准；
- 所有强基线、主实验与统计分析。
