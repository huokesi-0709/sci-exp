2026-07-28在当前Windows环境尝试逐条访问13个政府来源官方发布页，
均因网络策略返回“无法连接到远程服务器”。因此本轮没有把任何来源升级为
“已核验”，也没有根据站点可访问性推断版权或再分发权。尝试结果属于审计记录，
不是许可证证据。

这不是说来源一定不能使用，而是研究复现包不能在没有明确许可证据时把政府网页、
出版社PDF或镜像PDF重新打包公开。

## 核验规则

1. 记录官方发布页、实际下载地址、版本日期和本地SHA-256。
2. 优先查找官方版权页、开放许可标识、出版物许可条款和再分发限制。
3. 国际组织材料还要记录具体许可版本、署名、非商业和相同方式共享要求。
4. 政府网页和政府PDF不能默认属于公有领域；需记录页面版权声明或官方再利用政策。
5. 镜像只解决可获取性，不自动授予镜像方或研究者再分发权。
6. 论文实验可以保留本地研究副本和哈希，但论文或代码包公开前必须决定：
   - 只公开来源URL、版本、哈希和下载脚本；
   - 或取得明确许可后公开派生文本；
   - 或只公开不含正文的证据ID、定位和统计结果。

## 当前各类处理

| 来源类型 | 当前处理 |
|---|---|
| WHO/ICRC等国际组织出版物 | 已核验两份WHO页面为CC BY-NC-SA 3.0 IGO，仍需落实署名、非商业、相同方式共享和WHO标识限制 |

| 地方政府健康/消防页面 | 需要核对站点版权声明和转载限制 |
| 官方页面的PDF镜像 | 同时核对原发布机构和镜像站点的再分发条件 |

## 冻结条件

只有满足以下条件，才允许生成`正式协议库_v1`并在Radxa上进行正式主实验：

- 每份来源有可引用的许可证或再利用政策证据；
- 镜像下载地址的授权关系已记录；
- 版本、生效状态和失效/更新检查日期已记录；
- 派生章节的允许范围和排除范围已由双审确认；
- 公开包的正文、派生文本或仅元数据方案已明确；
- 生成新的版本清单、SHA-256和审计报告。

在此之前，`docs/sci-exp`可以复制到`/home/radxa/sci-exp`做脚本、索引和设备联调，
但不能把结果写成正式论文主实验结论。

## 自动检查

可在补齐官方版权、镜像授权和版本证据后运行：

```powershell
python scripts\检查正式协议库冻结门槛.py `
  --sci-exp-root . `
  --output data\logs\正式协议库冻结门槛检查_v0.1.json
```

只有输出中的`formal_library_freeze`、`formal_training_eligible`和
`radxa_main_experiment_eligible`同时为`true`，才允许生成正式协议库和
Radxa主实验输入包。当前检查结果为三个字段均为`false`，15份来源中
0份满足全部冻结条件。
