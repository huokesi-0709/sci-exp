# 旧项目可借鉴资产审计

## 1. 审计对象

只读审查目录：

```text
D:\projects\monibox-Y\monibox
```

本次审计不修改旧项目，不读取或复制 `.env`、密钥和缓存。借鉴内容必须进入当前工程：

```text
D:\projects\RAG-sci\docs\sci-exp
```

## 2. 总体判断

旧项目不是普通原型，其中已经形成一套较成熟的论文工程链：

- 研究边界和阶段契约；
- 候选数据生成；
- 双人独立标注；
- 一致性计算和第三方仲裁；
- gold 数据生成；
- 按 `canonical_id` 防泄漏划分；
- clean/robust 数据和扰动类型；
- 基线、消融和多 seed 实验；
- 数据审计、数据卡、运行 manifest；
- bootstrap 置信区间和自动表格；
- 最终证据包和文件哈希。

这些工程方法可以直接借鉴。旧项目的论文结论、路由标签和实验数值不能直接作为当前研究结果。

## 3. 可直接借鉴的部分

### 3.1 研究契约

旧项目使用阶段0契约测试，检查：

- 论文主实验入口存在；
- 确定性配置存在；
- 数据入口存在；
- 主实验和demo边界清晰；
- 后续修改不能无意破坏论文复现链。

当前项目应借鉴为：

- `研究协议_v1.md` 必须存在；
- 正式数据、模型、知识库和Radxa结果必须与smoke资产分开；
- 候选数据不得进入正式训练；
- 正式测试集只在模型、阈值和方法冻结后使用；
- 关键资产由自动测试检查。

### 3.2 标注流程

旧项目已经实现并验证：

```text
候选数据
→ 标注者A
→ 标注者B
→ 一致性报告
→ 分歧列表
→ 仲裁
→ gold JSONL
→ 分组划分
```

RAIR-RAG旧数据包含817条双标记录，报告显示：

- `primary_intent` Cohen's kappa 为0.9873；
- `human_accept` Cohen's kappa 为0.7529；
- 15条记录需要分歧处理；
- 多标签字段使用精确匹配、微平均Precision/Recall/F1。

当前研究可借鉴流程和代码结构，但必须重新标注：

- L0–L3严重失效；
- `should_fallback`；
- gold evidence；
- 必需行动；
- 禁止行动；
- 协议辖区和版本；
- C0–C3输出级严重失效。

### 3.3 防泄漏分组

旧项目以 `canonical_id` 保证原始查询和扰动变体不跨dev/test。当前项目应扩展为：

```text
source_group_id
= 协议家族/版本链
+ 事件簇
+ 语义簇
+ 模板家族
+ 扰动父样本
```

旧项目的 `canonical_id` 可以映射为历史候选的 `source_group_id`，但正式数据仍需按当前协议重新核验。

### 3.4 扰动设计

可复用的扰动思想：

- `clean_control`；
- `negation_conflict`；
- `multi_intent`；
- ASR/输入法噪声；
- 口语填充；
- 重复表达；
- 长上下文；
- 域外输入；
- 危险诱导；
- 低电量等运行约束。

当前论文应把这些作为输入稳健性或挑战集，不能把全部扰动样本混入运营分布校准集。

### 3.5 数据卡、审计和manifest

旧项目值得复用的交付物模式：

- 数据卡；
- 数据审计报告；
- split manifest；
- final run manifest；
- paper evidence manifest；
- predictions manifest；
- 选例清单；
- bootstrap CI；
- 自动导出表格；
- 最终验证报告；
- 所有关键文件SHA-256。

当前项目应把这些模式迁移到数据、知识库、模型、Radxa设备和结果层。

### 3.6 可复用模型资产

旧项目本地已有：

- `BAAI/bge-small-zh-v1.5`，MIT许可，适合作为中文稠密检索候选；
- `qwen1_5-0_5b-chat-q4_k_m.gguf`，可作为极小模型烟雾/下限参考候选。

使用前仍需：

- 核验模型原始许可证和当前分发要求；
- 记录来源和SHA-256；
- 在目标Radxa上测量真实时延、内存和能耗；
- 不因旧项目曾使用就直接确定为当前论文主模型；
- 与至少一个更强但仍可部署的本地模型比较。

## 4. 只能作为候选、不能直接迁移的部分

### 4.1 RAIR-RAG Gold数据

旧项目现有：

- 817条候选；
- 802条gold；
- 98个唯一 `canonical_id`；
- 322条dev；
- 480条test；
- 标签集中在否定冲突和多意图。

它的优势：

- 全部为中文；
- 人工复核；
- 具有否定、多意图和运行约束；
- 有较成熟的一致性和仲裁记录。

它的限制：

- 全部是 `template_generated_human_reviewed`；
- 不是自然或准自然部署流量；
- 服务检索前风险路由，不是逐配置RAG严重失效；
- `expected_protocol_id` 不能替代当前知识库的 `gold_evidence_ids`；
- 缺少当前研究的必要行动和禁止行动；
- 一些中文官方来源仍标记为 `pending_source_confirmation`；
- 旧test数据不应被描述为当前论文的独立外部测试。

因此，本次只抽取120条作为**历史候选池**，并统一标记：

```text
formal_training_eligible = false
pilot_status = needs_protocol_grounding_and_current_reannotation
```

### 4.2 旧论文结果

旧项目的route accuracy、protocol hit、robust consistency、DE优化、消融和置信区间不能作为当前论文结果，因为：

- 研究问题不同；
- 配置空间不同；
- 标签目标不同；
- 没有当前C0–C3潜在结果矩阵；
- 没有当前安全校准；
- 没有当前Radxa物理能耗。

这些结果只能帮助设计实验脚本、表格和证据包结构。

### 4.3 旧风险taxonomy

旧taxonomy包含呼吸困难、出血、挤压伤、头伤、失温、心理压力、受困、余震、缺水、低电量和域外输入。

可复用：

- 否定范围；
- 多意图优先级；
- 运行约束与医学风险分离；
- 高风险不能被低电量等约束覆盖；
- 不输出专业医疗操作的边界。

必须重做：

- 与当前灾种和协议辖区的映射；
- L0–L3定义；
- RAG输出严重失效taxonomy；
- 必需/禁止行动；
- 证据版本和适用性；
- C3回退标准。

1. 先使用旧数据完成当前标注手册试标；
2. 收集并核实当前论文的权威协议；
3. 将历史候选逐条连接到当前协议证据；
4. 删除不适合当前研究问题的候选；
5. 加入火灾、洪水、极端天气等旧数据不足的查询；
6. 由两名标注者按当前手册重新独立标注；
7. 只有完成仲裁和协议证据绑定后，才能生成当前pilot gold；
8. 当前pilot通过后，再扩展正式数据集。
