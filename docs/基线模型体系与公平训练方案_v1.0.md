# 离线应急 RAG 基线模型体系与公平训练方案 v1.0

**研究任务：**资源受限边缘设备上离线应急 RAG 的校准安全约束逐查询配置选择  
**目标：**建立从最简单参考到当前强基线的可复现实验阶梯  
**适用目录：**`D:\projects\RAG-sci\docs\sci-exp`，复制到 Radxa 后为 `/home/radxa/sci-exp`

## 1. 基线比较对象

本研究比较的是一个逐查询配置选择器：

\[
\pi(q,x)\rightarrow c,\quad c\in\{C0,C1,C2,C3\}
\]

其中 \(q\) 是查询，\(x\) 是部署时可观测的设备/资源状态，\(c\) 是配置。配置含义与当前项目一致：

| 配置 | 含义 | 当前冻结设置 |
|---|---|---|
| C0 | 无检索直接生成 | 相同生成模型，最多 512 tokens |
| C1 | 混合单步 RAG | candidate 20，evidence top-k 5，BM25+BGE+RRF |
| C2 | 协议感知混合多步 RAG | 每步 candidate 24，evidence top-k 8，协议过滤和重排 |
| C3 | 确定性安全回退 | 不调用生成模型，澄清/求救/转官方渠道 |

基线必须回答不同问题：

- 固定配置：是否需要逐查询选择；
- 传统 ML：简单风险/成本特征是否已经足够；
- 经典 AI+：加入文本语义和校准后是否改善选择；
- 当前强基线：在相同资源约束下，成熟的风险校准和约束选择器能达到什么水平。

## 2. 总体基线矩阵

| 编号 | 层级 | 基线名称 | 输入 | 输出 | 主要回答 |
|---|---|---|---|---|---|
| B0 | 简单 | 多数类固定策略 | 无 | 固定一个配置 | 逐查询选择是否比最弱参考更好 |
| B1 | 简单 | 固定 C0/C1/C2/C3 | 无 | 固定配置 | 各配置的安全、质量和资源上下限 |
| B2 | 简单 | 规则安全路由 | 查询规则 + 状态阈值 | C0–C3 | 人工安全规则能否达到可用水平 |
| B3 | 传统 ML | 逻辑回归路由 | 10 维手工查询特征 + 资源特征 | 配置风险分数 | 线性可解释模型的上限 |
| B4 | 传统 ML | 随机森林/梯度提升路由 | 同 B3 | 配置风险/成本预测 | 非线性表格模型是否有增益 |
| B5 | 经典 AI+ | BM25-only 配置基线 | BM25 检索特征 + 状态 | C0–C3 | 词法检索是否足以支撑选择 |
| B6 | 经典 AI+ | BGE-small 语义路由 | 本地 BGE-small 向量 + 状态 | C0–C3 | 轻量语义表示的增益 |
| B7 | 经典 AI+ | 混合检索+轻量 MLP 路由 | BM25、BGE、协议和状态特征 | C0–C3 | 经典 AI+特征融合的效果 |
| B8 | 当前强基线 | 校准风险约束成本选择器 | BGE-small + 完整可观测特征 | C0–C3 | 成熟的校准、约束和成本选择上限 |
| B9 | 上限参考 | Oracle / gold-evidence 参考 | gold 标签或事后结果 | 最优配置 | 可达到的理论差距，不作为部署方法 |

B0–B8 是部署可行或可复现的比较对象；B9 只能做 oracle gap，不参与普通方法排名。

## 3. 简单基线

### 3.1 B0 多数类固定策略

在 `train` 中统计最终选择配置的众数，整个验证和测试阶段只输出该配置。若尚未
有配置标签，则使用开发协议预注册为固定 C1，不能在测试集选择。

参数：

```text
策略：固定一个配置
训练参数：无
调参参数：无
随机种子：无
```

用途：提供最低复杂度参考，不能被解释为安全策略。

### 3.2 B1 固定配置

分别运行固定 C0、C1、C2、C3，每个查询都使用相同配置。当前项目参数固定为：

```text
生成模型：Qwen1.5-0.5B-Chat，Q4_K_M
temperature：0.0
maximum_generated_tokens：512
C1 candidate_k：20，evidence_top_k：5
C2 candidate_k：24，evidence_top_k：8，c2_min_evidence：3
检索：BM25 + BGE-small + weighted RRF，rrf_k：60
```

C3 不调用生成模型，必须单独报告其回退正确性、coverage、时延和能耗，不把它当作“效果很低的生成模型”。

### 3.3 B2 规则安全路由

使用预注册的安全优先级，不训练参数：

```text
若明显 L3 或出现立即生命危险 → C3 或“C2 后确定性回退”
若无适用证据/证据冲突/关键信息缺失 → C3
若有适用协议且风险可控 → C2
若风险较低但需证据 → C1
仅域外或无应急内容 → C0/C3，按规则冻结
```

规则只可使用部署时可观测查询和设备状态，不能读取 `gold_evidence_ids`、
`risk_level`、`should_fallback` 或测试输出。规则条数、优先级、阈值和人工开发记录
必须版本化；不得为每条测试查询单独写例外规则。

## 4. 传统机器学习基线

### 4.1 B3 逻辑回归风险路由

这是当前 `src/sci_exp/risk_model.py` 中最接近的轻量基线。对每个配置训练一个
二元风险模型，预测该配置产生严重失效的概率。

输入特征：

```text
token_count
character_count
has_question_mark
urgency_term_count
hazard_term_count
context_term_count
negation_count
multi_intent_connector_count
has_numeric_detail
surface_insufficient_information
```

设备状态可作为第二版扩展，但必须对所有传统 ML 基线同时开放同一组状态特征。

参数固定为：

```text
iterations：1200
learning_rate：0.1
l2：0.01
特征标准化：仅使用 train 拟合均值和尺度
类别处理：训练集中的加权 BCE 或 class_weight=balanced
概率校准：只在 cal_op 拟合，不在 test 上调阈值
```

选择规则：

\[
\min_c \widehat{E}[\text{energy}(c)]
\quad
\text{s.t. } \widehat{P}(\text{severe failure}\mid c)\le \alpha
\]

若没有满足约束的配置，选择 C3。

### 4.2 B4 随机森林或梯度提升路由

B4 用于检验非线性表格特征是否超过 B3。推荐先实现一个版本，不能同时挑选多个
算法并只报告最好的一个。

推荐配置（以梯度提升树为主）：

```text
算法：HistGradientBoostingClassifier 或同等 CPU 实现
最大树数：200
learning_rate：0.05
max_depth：4
min_samples_leaf：10
l2_regularization：1.0
early_stopping：true
validation_fraction：固定 valid
random_state：11/23/37/51/71
```

若使用随机森林作为敏感性实验：

```text
n_estimators：200
max_depth：8
min_samples_leaf：3
max_features：sqrt
class_weight：balanced
```

B4 不能使用 BGE 向量、gold evidence 或模型生成文本，否则不再是传统 ML 基线。

## 5. 经典 AI+ 基线

### 5.1 B5 BM25-only 配置基线

只使用本地协议库的 BM25 检索统计，不使用 BGE dense embedding：

```text
candidate_k：20
top_k：5
k1：1.2
b：0.75
rerank：关闭
协议过滤：保持与 C1 相同的版本/辖区/有效期过滤
```

输入特征包括 top-1/top-5 分数、分数间隔、有效证据数、冲突标记和查询表面特征。
所有参数在 valid 冻结。

### 5.2 B6 BGE-small 语义路由

使用项目已冻结的 `BAAI/bge-small-zh-v1.5` 本地模型生成查询向量和协议候选向量。
不训练 dense encoder，避免边缘资源和训练预算膨胀。

```text
embedding：bge-small-zh-v1.5
distance：cosine
candidate_k：20
top_k：5
归一化：L2
训练头：单层 logistic 或线性 softmax
```

编码器权重、版本和 SHA-256 必须与 C1/C2 一致。B6 的增益只能归因于语义检索特征，
不能同时改变生成模型或知识库。

### 5.3 B7 混合检索+轻量 MLP

这是经典 AI+的主要基线：融合 BM25、BGE、协议适用性和设备状态特征，用小型 MLP
预测每个配置的风险/成本。

结构：

```text
输入：BM25 统计 8 维 + BGE 相似度 8 维 + 协议适用性 6 维
      + 查询手工特征 10 维 + 设备状态 4 维
隐藏层：64 → 32，ReLU
Dropout：0.10
输出：每个配置的严重失效概率和资源回归值
损失：加权 BCE + 0.1 × Huber(resource)
优化器：AdamW
learning_rate：1e-3
weight_decay：1e-4
batch_size：32
max_steps：1200
early_stopping：valid 主指标连续 20 个评估点无提升
```

B7 使用统一校准和安全约束选择器，但不使用 conformal 或复杂不确定性估计；这样
可以区分“特征融合增益”和“安全校准机制增益”。

## 6. 当前强基线

### 6.1 B8 校准风险约束成本选择器

B8 是本研究应优先实现的当前强基线。它使用轻量语义表示、配置级风险预测、概率
校准和资源约束选择，但不使用本文拟提出的额外结构或事后信息。

模块：

```text
查询/协议特征
→ BGE-small 冻结编码
→ 64→32 MLP 多任务头
→ 每配置风险概率校准
→ conformal 或分位数风险上界
→ 延迟/内存/能耗硬约束过滤
→ 在可行配置中最小化预测能耗
```

推荐参数：

```text
编码器：BAAI/bge-small-zh-v1.5，冻结
MLP：64→32，ReLU，Dropout=0.10
风险头：4 个配置 × 1 个 sigmoid
资源头：4 个配置 × 3 个回归量（latency/memory/energy）
损失：0.7 × BCE_risk + 0.3 × Huber_resource
class_weight：按 train 计算，封顶 5.0
optimizer：AdamW
learning_rate：1e-3，cosine decay
weight_decay：1e-4
batch_size：32
max_steps：1200
early_stopping：valid 上的安全优先指标，patience=20
校准：temperature scaling 或 isotonic，只用 cal_op
风险容忍：alpha=0.05
安全裕量：delta=0.05
设备预算：memory=6144 MB，latency=30000 ms
```

选择函数：

\[
\hat c=\arg\min_{c\in\mathcal F(q,x)}
\widehat E_c(q,x)
\]

\[
\mathcal F(q,x)=\{c:
U_c^{risk}(q)\le \alpha,\ 
\widehat{M}_c(x)\le M_{\max},\
\widehat{T}_c(x)\le T_{\max}\}
\]

若 \(\mathcal F(q,x)=\varnothing\)，强制选择 C3。B8 不可使用 `gold_evidence_ids`、
未来实验结果、仲裁后的输出文本或测试集标签。

### 6.2 B9 Oracle 上限参考

B9 可以使用 gold evidence、最终人工标签或已知真实资源结果，在每条查询上选择安全
且质量最高的配置。它只用于计算：

```text
oracle gap
regret
可达到的 coverage 上限
```

B9 不训练、不校准、不参与模型排名，也不能被称为可部署基线。

## 7. 统一公平训练原则

### 7.1 数据角色

所有学习基线使用相同数据角色：

| 数据集 | 允许用途 |
|---|---|
| `train` | 参数训练、类别权重、特征标准化 |
| `valid` | 早停、普通超参数和 checkpoint 选择 |
| `cal_op` | 概率校准和安全阈值 |
| `cal_ch` | 只做偏移检查，不重新调阈值 |
| `test_op`、`test_ch` | 只做一次最终评估 |

当前 400 条数据仍是 `development_gold`，不能进入最终确认性测试。

### 7.2 统一生成与知识库

- C0–C2 使用同一 Qwen1.5-0.5B-Chat、同一 Q4_K_M 量化和 512 token 上限；
- C1/C2 使用同一知识库版本、分块、协议过滤和许可证状态；
- C3 的低成本确定性行为单独报告；
- 所有方法使用同一查询 ID 清单，失败、超时、OOM 不能静默删除；
- 任何基线若改变生成模型或知识库，必须另列为“官方复现/生态参考”，不能混入匹配容量主表。

### 7.3 参数量与训练预算

匹配容量比较时：

- B3/B4/B7/B8 使用相同训练样本、最大 optimizer steps、batch size 和早停规则；
- B7/B8 使用相同输入特征上限和相同 MLP 总参数预算，只有校准/约束模块不同；
- 记录总参数、可训练参数、模型文件大小、峰值内存、每查询时延和能耗；
- 不能只报告主生成模型参数而忽略编码器、重排器和路由头。

### 7.4 超参数搜索

所有可训练基线使用相同的搜索预算：

```text
每种方法最多 30 个 trial
搜索只在 train/valid
选择规则：先满足 valid 安全门槛，再最大化行动完整率，最后最小化资源
cal_op 只做校准，不选择网络结构
test_op/test_ch 禁止调参
```

若某方法必须使用论文官方参数，保留官方结果为单独轨道，并报告其额外预训练、
数据和 trial 数。

### 7.5 随机种子与重复

至少记录并区分：

```text
split_seed：42
train_seed：11, 23, 37, 51, 71
generation_seed：101, 103, 107
order_seed：211, 223, 227
bootstrap_seed：单独记录
```

温度为 0 也必须记录 generation seed 和后端确定性设置。每个
`query_id × configuration × repetition` 必须配对；重复运行不能只改变任务顺序。

## 8. 统一评价与排名规则

主结果分为三条轴：

1. **安全：**L3 严重失效率、风险约束越界率、危险行动违反率；
2. **服务：**总 coverage、回退正确率、必需行动完整率、证据正确率；
3. **资源：**每到达查询能耗、每安全完整回答能耗、P95 时延、峰值内存。

公平比较必须同时报告：

- fixed-risk：相同 \(\alpha,\delta\) 下比较 coverage 和资源；
- matched-coverage：coverage 相近时比较风险和质量；
- 系统级 Pareto 前沿：风险—coverage—能耗；
- C3 回退比例及其正确性；
- 失败、超时、OOM 和缺失输出计入分母。

只有满足预注册安全约束的方法，才可参与“资源最优”排序。B9 oracle 仅报告 gap。

## 9. 基线实现顺序

建议按以下顺序落地：

1. B1 固定 C0/C1/C2/C3，验证运行接口和资源采集；
2. B2 规则安全路由，冻结规则和日志；
3. B3 复用当前逻辑风险模型，补齐校准和阈值分离；
4. B5/B6 建立 BM25-only 和 BGE-small 特征；
5. B4/B7 完成传统非线性和轻量 MLP；
6. B8 实现校准、风险上界、资源硬约束和 C3 fallback；
7. 最后实现 B9 oracle gap，不将其混入部署模型；
8. Windows 完成训练、校准和配置冻结，再复制到 Radxa；
9. Radxa 只运行冻结模型和配置，生成输出后进行盲法输出级审查。

## 11. 通过门槛

基线体系在进入正式比较前必须满足：

- B1 四个固定配置均能在同一查询集运行；
- B3、B4、B7、B8 不读取测试 gold 或模型输出；
- 每个学习基线都有 train/valid/calibration/test 的角色记录；
- 至少 3 个训练 seed，推荐 5 个；
- 所有方法保留失败和回退样本；
- C3 单独报告，不被归类为高质量生成配置；
- 当前 smoke 结果不进入论文主结果；
- Radxa 运行前已冻结模型、配置、数据和评价 rubric。
