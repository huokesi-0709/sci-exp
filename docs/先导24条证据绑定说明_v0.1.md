日期：2026-07-27  
状态：机器建议已生成，等待双人独立审查与仲裁

## 1. 本批次用途

本批次用于试运行“查询—协议证据—行动槽位—风险等级—回退决策”的标注
流程，发现标签体系和协议覆盖问题。它不是正式训练、校准或测试数据。

24条查询从旧项目120条历史候选中确定性选出，并保证
`source_group_id` 不重复。意图配额为：

| 意图 | 条数 |
|---|---:|
| 严重出血或休克 | 3 |
| 创伤或骨折 | 3 |
| 意识改变或头部损伤 | 2 |
| 呼吸困难 | 3 |
| 低温风险 | 2 |
| 被困 | 3 |
| 余震或坍塌风险 | 2 |
| 挤压伤 | 2 |
| 缺水或资源匮乏 | 1 |
| 心理困扰 | 1 |
| 低电量 | 1 |
| 域外问题 | 1 |

## 3. 机器建议的含义

候选证据由“查询文本＋意图检索提示”的BM25排序产生，并先按灾种标签过滤。
它只帮助审查者定位可能相关的段落，不承担 gold 标注功能。

以下字段必须保持不变，直至双审和仲裁完成：

- `formal_training_eligible=false`；
- `gold_evidence_ids=[]`；
- `split=""`；
- `evidence_binding_status=machine_suggestion_pending_double_review`。

候选列表为空不等于系统错误。本批次预设4类证据空白控制：

- 缺水或资源匮乏；
- 心理困扰；
- 低电量；
- 域外问题。

这些控制用于验证标注者是否会在缺少适用协议时选择证据不足或安全回退，
而不是强行绑定不相关段落。

## 4. 双人独立审查

审查者A和B不得互看对方填写结果。每条查询分别填写：

1. 接受的证据ID；
2. 必需行动；
3. 禁止行动；
4. L0–L3风险等级；
5. 是否应回退；
6. 判断理由和不确定性。

审查时必须打开完整候选切块，不能只根据 `text_preview` 判断。机器首选证据
可能只匹配到同一页中的相邻主题，也可能匹配到错误灾种。例如“被困”查询如果
未说明火灾、洪水或地震背景，不应仅因词语相似就绑定某一灾种协议。

建议用竖线分隔多个ID或行动槽位，例如：

```text
EVIDENCE_001|EVIDENCE_002
```

如无适用证据，应保持证据ID为空，并在备注中说明：

- 当前来源确实没有覆盖；
- 查询缺少确定适用协议所需的灾种或情境信息；
- 来源存在但版本、辖区、对象或许可证状态不满足；
- 需要补充哪一类权威来源。

## 5. 仲裁与通过标准

出现以下任一情况必须仲裁：

- A/B接受的证据集合不同；
- A/B的L0–L3不同；
- A/B对是否回退判断不同；
- 必需行动或禁止行动存在冲突；
- 任一审查者认为协议越权、过期、适用对象错误或存在临床安全疑问。

只有完成仲裁且协议内容本身通过双审后，才可把记录转为新的标注版本。不得直接
覆盖本文件，也不得把机器候选字段复制为 `gold_evidence_ids`。

本轮建议的质量控制门槛：

- 24条全部双审，无缺失单元格；
- 证据ID均存在于同一版本的精选候选切块；
- 机器建议接受率、拒绝率和空白率均被报告；
- L0–L3与回退决策的一致性被计算；
- 任何高风险操作均有专家复核；
- 所有修改采用追加式版本和新SHA-256。

是否有直接面向公众、版本可核验的权威中文材料。
