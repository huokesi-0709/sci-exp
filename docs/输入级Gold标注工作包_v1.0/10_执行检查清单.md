# 输入级 Gold 执行检查清单

## A. 启动前

- [ ] 已确认本批次是 training、pilot、development、calibration 或 test 中哪一种用途。
- [ ] 当前 400 条仍标记为 `development_gold`，没有自动升级。
- [ ] 查询和 `source_group_id` 已冻结。
- [ ] 数据分区未使用未来 Gold 标签调整。
- [ ] 协议语料、来源卡、许可、版本和哈希已冻结。
- [ ] 手册、本体和 Schema 版本一致。
- [ ] 领域审核者已审核标签定义和本体。
- [ ] A/B 已完成培训和独立试标。
- [ ] 已记录伦理/隐私审批、豁免或机构不适用认定状态。

## B. 独立标注

- [ ] A/B 使用互不可见文件和不同随机顺序。
- [ ] A/B 看不到旧开发标签、模型结果、配置和能耗。
- [ ] 正式标注期间没有修改手册或本体。
- [ ] 所有集合字段使用受控 ID。
- [ ] A/B 分别提交并计算 SHA-256。
- [ ] 结构错误修复保留旧版本和修改记录。

## C. 一致性

- [ ] A/B query ID 集合完全一致且无重复。
- [ ] query text、source group、手册、语料和本体版本配对一致。
- [ ] 一致性使用原始 A/B 文件，尚未仲裁。
- [ ] 报告包含 kappa、原始一致率、分歧矩阵和集合指标。
- [ ] 95% CI 按 `source_group_id` 聚类 bootstrap。
- [ ] A/B 输入文件和报告均记录 SHA-256。
- [ ] 统计复核者完成复核。

## D. 仲裁和质量控制

- [ ] 全部 categorical 和集合分歧已仲裁。
- [ ] 100% S3、升级 YES、evidence gap 已由 C 复核。
- [ ] 低风险一致项已按冻结比例随机抽检。
- [ ] 无 required/prohibited 交集。
- [ ] critical 是 required 子集。
- [ ] 所有 evidence ID 和跨度真实存在且适用。
- [ ] 无法确定的记录保留 Unknown/UNRESOLVED/EXCLUDED，没有强填。
- [ ] 手册或本体变化已完成全批影响分析。

## E. 冻结

- [ ] 最终 Gold 由程序合并并通过 Schema。
- [ ] 每个字段能追溯到 AGREED_AB 或具体仲裁记录。
- [ ] 冻结 manifest 包含文件哈希、版本、Git commit 和时间。
- [ ] C、S、T 审核状态完整。
- [ ] Gold 文件保存在 `data/annotations/`，未同步到 Radxa。
- [ ] 只有 Gold-free `InferenceQuery` 可进入推理设备。
- [ ] 论文只报告真实人员、真实过程和真实仲裁前指标。
