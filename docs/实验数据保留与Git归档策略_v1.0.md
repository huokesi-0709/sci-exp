# 实验数据保留与Git归档策略 v1.0

## 核心原则

代码Git仓库不是高频原始遥测的长期存储。完整raw、Git摘录和分析报告承担不同职责：

|层级|保存内容|进入Git|能否重做完整统计|
|---|---|---|---|
|完整raw|所有sample/environment/marker记录|否，外部压缩归档|可以|
|摘录|header、meta、开头和结尾少量记录|可以|不可以|
|报告|样本数、时长、误差、间隔、丢样和门槛结果|可以|只能核对结论|
|manifest|文件哈希、大小、位置、保留状态|可以|用于证据寻址|

## 推荐命名

```text
外部归档：INA226_E0_session002.full.jsonl.gz
Git摘录： INA226_E0_session002.excerpt.jsonl
Git清单： INA226_E0_session002.manifest.json
Git报告： E0_session002_report.json
```

不得将摘录继续命名为`*.full.jsonl`或原始采集文件名。

## 每次采集后的顺序

1. 采集器关闭并确认最终计数。
2. 对完整文件计算SHA-256、字节数和记录数。
3. 压缩完整文件，验证压缩包可以解压读取，并记录压缩包SHA-256。
4. 将压缩包复制到Git之外的持久目录或研究数据仓库。
5. 另行生成首尾摘录，不修改完整文件。
6. 在Git中提交manifest、摘录和分析报告。
