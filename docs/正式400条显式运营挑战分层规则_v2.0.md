# 正式400条显式运营/挑战分层规则 v2.0

## 1. 适用范围

本规则只适用于当前400条`development_gold`开发数据，用于工程开发、先导校准、
Radxa联调和流程验证。它不是研究协议v2.0规定的3,600条最终确认性数据，其中
L3、C3或域外比例也不代表真实发生率。

## 2. 不再使用哈希决定数据角色

v1.0按`source_group_id`计算SHA-256，再由哈希决定六分区。该方法能避免组泄漏，
但不能解释某条记录为何属于运营集或挑战集。

v2.0禁止使用哈希决定分区：

1. 先按预声明场景规则确定挑战校准、挑战测试和严格外推子集；
2. 其余记录组成运营候选池，以来源组为不可拆分单位，按灾种、L3、C3、
   查询类型和证据来源进行确定性分层。

字典序只用于相同目标函数值时的稳定并列裁决，不承担随机分配功能。

## 3. 不可拆分单位和近重复

基础不可拆分单位为：

```text
source_group_id = 事件簇 | 协议家族 | 协议版本链
```

查询文本先执行NFKC标准化和字符2/3-gram余弦近重复检测：

- 相似度≥0.88：进入近重复复核表；
- 不同`source_group_id`且相似度≥0.94：合并为同一`partition_unit_id`；
- 同一`partition_unit_id`禁止跨分区。

v1.0发现10个完全重复域外文本簇。v1.1修订17条后，400条文本全部唯一，
在0.88阈值下没有剩余近重复对；最终形成65个不可拆分来源组。

## 4. 挑战测试 `test_ch`

### 4.1 时间外

- 时间切点：2026-04-01；
- 留出协议家族：`MEM_FLOOD_PREPAREDNESS_2026`；
- 生效日期：2026-06-23；
- 引用该协议家族的完整来源组只进入`test_ch`。

该规则产生37条时间外查询。

### 4.2 地区外

- 留出辖区：`CN-SX-JC`；
- 留出协议家族：`JINCHENG_HIGHRISE_FIRE_2026`；
- 引用该地区协议家族的完整来源组只进入`test_ch`。

该规则产生28条地区外查询。

### 4.3 域外控制

将一个完整域外来源组分配到`test_ch`，产生6条域外控制。因此`test_ch`
共71条，并同时覆盖L3、C3、否定冲突、时间外、地区外和域外请求。

## 5. 挑战校准 `cal_ch`

其余域外来源组进入`cal_ch`。然后从尚未分配且不是严格时间/地区留出的来源组中，
分别补入满足L3、C3和否定冲突条件的最小完整来源组。

`cal_ch`只用于挑战诊断和分组校准，不选择确认性主阈值。

## 6. 运营四分区

排除时间外、地区外和域外控制后，剩余来源组构成运营候选池。运营池内部名义权重为：

| 分区 | 权重 |
|---|---:|
| `train` | 0.48 |
| `valid` | 0.12 |
| `cal_op` | 0.16 |
| `test_op` | 0.24 |

分配时以完整`partition_unit_id`为单位，依次保持L3、C3和否定冲突配额，再平衡
灾种、查询类型、证据来源和分区规模。`cal_op/test_op`禁止包含明确的时间外、
地区外和域外控制。

## 7. 日期、辖区、版本和行动槽位

冻结前必须同时通过：

- 所有`gold_evidence_ids`存在；
- 所有协议具有辖区；
- 生效日期可解析且不晚于冻结日2026-07-28；
- 查询声明的协议家族与证据来源一致；
- 版本链包含全部绑定证据版本；
- 必需行动和禁止行动不存在标准化完全重合；
- 去除否定词后的高相似行动对进入复核。

本版严格冲突和待复核行动冲突均为0。

## 8. 版本外测试边界

当前13个协议家族各只有一个纳入版本，不能构造真正的同家族版本外测试。
不能把“不同来源”或“不同发布日期”伪装成版本外。后续必须补入同一协议家族
的前版和后续修订版，按版本链整体留出新版，才能设置`version_ood=true`。

## 9. 冻结门槛

- 400条标准化文本全部唯一；
- 至少40个独立来源组；
- 全局至少100条L3、100条C3和30条域外对照；
- 六分区非空，来源组和近重复单元均无泄漏；
- 运营四分区均包含L3和C3；
- `cal_ch/test_ch`满足预声明挑战覆盖；
- 只有`train`允许未来添加增强样本；
- 全部记录完成正式仲裁。
