# 样本量与实验重复次数估算

## 1. 估算对象

本研究包括三类不同的样本量问题：

1. **查询样本量**：用于比较 PROPOSED 与基线的严重失效、行动完整率和配置选择；
2. **独立校准样本量**：用于选择满足风险上界的配置接受阈值；
3. **Radxa 重复运行次数**：用于估计时延、能耗、内存和持续热负载。

这三类数量不能互相替代。增加同一查询的设备重复不能提高安全结局的独立查询数；
增加查询数也不能替代独立设备会话对热态测量误差的估计。

## 2. 主要结局指标

建议只设置一个确认性安全主比较：

> PROPOSED 与固定强配置 F2，或与同架构未校准强基线 S2，在相同查询和 matched
> coverage 下的配对 L3 严重失效率差异。

需要在预注册中从 F2 和 S2 选择一个作为唯一主要确认性对照。另一个作为关键次要
比较，避免五个对照同时消耗显著性水平。

### 2.1 主要结局

- 配对 L3 严重失效，二元结局；
- 统计检验：McNemar 检验；
- 效应量：绝对风险差；
- 同时报告风险比和精确置信区间。

### 2.2 关键次要结局

- risk@coverage 和总服务 coverage；
- 必要行动完整率；
- 焦耳/到达查询；
- P95 端到端时延；
- 约束越界频率；
- C3 回退是否恰当。

资源节省只能在满足安全约束的方法之间比较。

## 3. 显著性水平与统计功效

建议设置：

| 项目 | 推荐值 |
| --- | ---: |
| 主要比较双侧显著性水平 | \(\alpha_{\mathrm{test}}=0.05\) |
| 最低统计功效 | 80% |
| 安全研究优选统计功效 | 90% |
| 校准风险容忍度 | \(\alpha_{\mathrm{risk}}=0.05\) |
| 校准失败概率 | \(\delta=0.05\) |
| 多配置校准 | \(\delta_c=\delta/3\) |

必须区分检验显著性水平 \(\alpha_{\mathrm{test}}\) 和系统风险容忍度
\(\alpha_{\mathrm{risk}}\)。二者虽然都常写作 \(\alpha\)，含义完全不同。

如果将五个方法比较都声明为同等主要比较，并以保守
\(\alpha_{\mathrm{test}}=0.01\) 规划，样本量会大幅增加。更合理的做法是只预注册
一个确认性安全主比较，其余使用层级检验或 Holm 校正。

## 4. 安全主结局的效应量假设

正式样本量必须在 100–150 条查询的先导实验后更新。先导实验前采用下列规划假设：

- 强基线 L3 风险：5%；
- PROPOSED L3 风险：3%；
- 目标绝对风险下降：2 个百分点；
- 两种方法均失败：1%；
- 仅基线失败：4%；
- 仅 PROPOSED 失败：2%；
- 配对不一致总比例：

\[
p_{10}+p_{01}=0.04+0.02=0.06;
\]

- 配对风险差：

\[
\Delta=p_{10}-p_{01}=0.02.
\]

这里 \(p_{10}\) 表示基线失败而 PROPOSED 不失败，\(p_{01}\) 表示 PROPOSED 失败
而基线不失败。

该假设比简单把 5% 和 3% 当作两个独立比例更符合本研究设计，因为同一查询会运行
所有配置和路由策略。

## 5. McNemar 配对样本量

使用大样本近似：

\[
n
\approx
\frac{
\left[
z_{1-\alpha/2}\sqrt{p_{10}+p_{01}}
+z_{1-\beta}
\sqrt{p_{10}+p_{01}-(p_{10}-p_{01})^2}
\right]^2
}{
(p_{10}-p_{01})^2
}.
\]

在绝对风险差保持 2 个百分点时，样本量高度依赖两方法的不一致率。

### 5.1 双侧 \(\alpha=0.05\)

| 不一致总比例 | 80%功效 | 90%功效 |
| ---: | ---: | ---: |
| 4% | 783 | 1,047 |
| 6%（主假设） | 1,175 | 1,572 |
| 8% | 1,567 | 2,097 |

向上取整并预留少量分析余量后：

- 80%功效建议 **1,200 条最终有效测试查询**；
- 90%功效建议 **1,600 条最终有效测试查询**。

### 5.2 当前1,080条测试集的功效

在主假设 \(p_{10}+p_{01}=0.06\)、\(\Delta=0.02\) 下：

\[
\operatorname{Power}(n=1080)\approx76.6\%.
\]

因此，现有 1,080 条同分布测试查询接近但未达到 80% 功效。它可以作为预算受限
方案，但需要：

- 在先导实验后重新估计 \(p_{10}\) 和 \(p_{01}\)；
- 使用配对精确/模拟功效而非只套用当前假设；
- 将“功效略低”写入局限；
- 不通过增加同一查询重复次数冒充独立样本。

### 5.3 多个确认性比较

如果五个比较都按 \(\alpha=0.01\) 独立规划，在主不一致假设下：

| 功效 | 所需最终有效查询 |
| ---: | ---: |
| 80% | 1,749 |
| 90% | 2,227 |

这说明把所有基线都设为主要比较会显著抬高样本量。建议：

1. 一个主要确认性比较使用双侧 0.05；
2. 其余关键比较按预注册层级顺序；
3. 探索性比较使用 Holm–Bonferroni；
4. 同时报告效应量与区间，不以“是否显著”作为唯一判断。

## 6. 独立校准集样本量

安全校准关心的是“被阈值接受的查询数”，而不是校准集总数。

对配置 \(c\)，若接受样本中观察到 \(k\) 次 L3，要求单侧
Clopper–Pearson 上界不超过：

\[
\alpha_{\mathrm{risk}}=0.05.
\]

### 6.1 单配置 \(\delta=0.05\)

| 接受样本中L3次数 | 最少接受样本数 |
| ---: | ---: |
| 0 | 59 |
| 1 | 93 |
| 2 | 124 |
| 3 | 153 |
| 4 | 181 |

### 6.2 三配置联合控制

使用：

\[
\delta_c=\frac{0.05}{3}\approx0.0167
\]

时：

| 接受样本中L3次数 | 每配置最少接受样本数 |
| ---: | ---: |
| 0 | 80 |
| 1 | 119 |
| 2 | 153 |
| 3 | 184 |
| 4 | 214 |

例如，校准集为 720 条、某配置 coverage 为 25%，则期望接受：

\[
720\times0.25=180
\]

条。该数量足以在最多观察到 2 次 L3 时证明上界不超过 5%，但不足以容纳 3 次
L3 所需的 184 条。

### 6.3 校准集建议

- 最低：720 条最终有效校准查询；
- 推荐：800–900 条；
- 若预计某配置 coverage 低于 15%，应扩大校准集或接受该配置无法取得非空安全
  阈值；
- 不能为了使阈值可行而删除校准错误；
- `cal_ch` 只检查偏移，不并入 `cal_op` 重新选阈值。

建议以：

\[
N_{\mathrm{cal}}
\geq
\frac{n_{\mathrm{accepted,required}}}
{\text{预期coverage}}
\]

反推总校准量。

## 7. 连续结局的样本量

### 7.1 能耗

假设主要资源比较为配对 log-energy：

- 期望节能：10%；
- 平均 log 差：

\[
\mu_d=\log(1.10)\approx0.0953;
\]

- 配对 log 差标准差：0.30；
- 标准化效应：

\[
d_z=\frac{0.0953}{0.30}\approx0.318.
\]

配对均值近似所需查询数：

\[
n
\approx
\left(
\frac{z_{1-\alpha/2}+z_{1-\beta}}{d_z}
\right)^2.
\]

| 配对log差标准差 | 80%功效 | 90%功效 |
| ---: | ---: | ---: |
| 0.20 | 35 | 46 |
| 0.30（主假设） | 78 | 104 |
| 0.40 | 138 | 185 |

考虑热状态分层、非正态和设备会话聚类，每个主要设备状态建议至少：

- 120–150 条独立查询用于平均/中位能耗比较；
- 300 条用于稳健估计 P95、热态交互和挑战切片。

因此，当前持续负载实验中每状态 300 条查询在查询数量上合理，真正不足的是独立设备
会话次数。

### 7.2 行动完整率

如果预期标准化配对效应 \(d_z=0.20\)：

- 80%功效约需 196 条；
- 90%功效约需 263 条。

安全主结局所需的 1,200–1,600 条测试查询通常已经覆盖这一要求。行动完整率不应
成为决定总测试样本量的主导因素。

### 7.3 P95时延

P95 的方差取决于完整分布，不能只凭均值和标准差可靠估算。建议：

- 先导阶段每配置至少 100–150 次运行；
- 主实验每策略×设备状态至少 300–500 个完成查询；
- 使用会话级 bootstrap 或分位数回归；
- 不能把同一会话内几百次请求当作几百个独立设备会话。

## 8. 生成随机种子和设备重复

### 8.1 生成seed

如果 temperature=0 且后端经验证确定：

- 质量主实验可使用 1 个固定生成 seed；
- 额外重复用于检查后端非确定性，而不是扩大查询样本量。

如果使用随机解码：

- 最低 3 个预注册生成 seed；
- 推荐 5 个 seed 做敏感性；
- 主安全标签可定义为“任一 seed 发生 L3”；
- 训练、校准和测试必须使用一致的 seed 风险定义。

当前方案的 3 个 generation seeds 可以作为预算可行下限。

### 8.2 单查询资源重复

先执行：

\[
30\text{ queries}\times3\text{ configurations}
\times5\text{ repeats}
\]

的资源先导测量，估计同条件变异系数：

| 同条件CV | 建议重复次数 |
| ---: | ---: |
| \(\leq10\%\) | 3 |
| 10%–20% | 5 |
| \(>20\%\) | 8，或先修正测量与后台负载 |

重复应随机化配置顺序，并区分冷态、预热和稳态。

### 8.3 持续负载会话

同一连续负载会话内请求高度相关。对于策略×设备状态：

- 当前 3 个独立会话只适合工程试验；
- 最低建议 6 个独立会话；
- 若热退化交互是主要结论，推荐 10 个独立会话；
- 会话应跨重启、时间段或实验区组；
- 查询顺序采用拉丁方或平衡随机化。

单台 Radxa 只能支持对该设备实例的结论。如果论文声称适用于某一设备型号而非这
一块板，建议至少使用 3 块独立同型号设备，并把设备作为随机效应。

## 9. 模型训练重复

学习模型建议使用 5 个训练 seed：

\[
\{11,23,37,51,71\}.
\]

训练 seed 用于估计优化不稳定性，不增加测试查询数。每个 seed：

- 使用相同 train/valid/cal/test 划分；
- 按 valid 规则自动选择 checkpoint；
- 独立校准阈值，或按预注册方案冻结一个部署模型后只校准一次；
- 不根据 test 选择最佳 seed；
- 报告所有 seed，包括训练失败。

简单逻辑回归若采用确定性凸优化，可只训练一次，但仍应通过 group bootstrap 或
重划分稳健性评估数据不确定性。

## 10. 数据损耗

可能的数据损耗包括：

| 损耗来源 | 规划比例 |
| --- | ---: |
| 去重、同源合并和模板泄漏控制 | 8% |
| 无法裁决或缺少关键标签 | 5% |
| 协议解析、来源或版本不合格 | 3% |
| Radxa运行失败、日志损坏或功率缺失 | 5% |

按乘法保留率：

\[
r
=
0.92\times0.95\times0.97\times0.95
\approx0.805.
\]

即总体可能损耗约 19.5%，建议按 20% 规划。所需原始样本：

\[
N_{\mathrm{raw}}
=
\frac{N_{\mathrm{final}}}{0.805}
\approx1.24N_{\mathrm{final}}.
\]

示例：

| 最终有效样本 | 建议原始收集量 |
| ---: | ---: |
| 测试1,200 | 约1,490 |
| 测试1,600 | 约1,990 |
| 校准800 | 约995 |
| 校准900 | 约1,120 |
| 总计4,200 | 约5,220 |
| 总计4,400 | 约5,470 |
| 总计5,350 | 约6,650 |

运行失败、OOM 和超时原则上是系统结果，不应自动当作数据损耗删除。只有日志无法
恢复、功率计失效等测量不可用情况才作为缺失，并应单独报告。

### 11.1 预算受限最低方案

| 数据角色 | 最终有效数量 |
| --- | ---: |
| train | 1,440 |
| valid | 360 |
| cal_op | 800 |
| test_op | 1,200 |
| OOD适应/测试 | 600 |
| 合计 | 4,400 |

按20%损耗，建议原始准备约5,500条。

该方案在主效应假设下接近80%功效，适合作为论文最低确认性方案。

### 11.2 安全优选方案

| 数据角色 | 最终有效数量 |
| --- | ---: |
| train | 1,800 |
| valid | 450 |
| cal_op | 900 |
| test_op | 1,600 |
| OOD适应/测试 | 600 |
| 合计 | 5,350 |

按20%损耗，建议原始准备约6,650条。

该方案使安全主比较接近90%功效，并提高稀有L3训练事件数和校准阈值稳定性。

## 12. 预计运行规模

不建议把所有生成 seed、设备状态和硬件重复完全做笛卡尔积。可分成两个实验。

### 12.1 安全与质量潜在结果矩阵

最低方案：

\[
1,200\text{ queries}
\times3\text{ generating configurations}
\times3\text{ generation seeds}
=10,800\text{ generation runs}.
\]

C3 主要是回退决策和模板输出，可单独记录，不必与完整生成配置使用相同重复设计。

优选方案：

\[
1,600\times3\times3
=14,400\text{ generation runs}.
\]

### 12.2 资源与热态实验

可使用分层抽取的 300 条查询：

\[
300\text{ queries}
\times3\text{ configurations}
\times3\text{ device states}
\times3\text{ measurement repeats}
=8,100\text{ runs}.
\]

另外对每个主要策略×设备状态安排至少6个、优选10个连续负载会话。这样避免将昂贵
的设备重复施加到全部安全测试查询。

## 13. 先导实验后的更新规则

先导实验使用100–150条分层查询，估计：

- \(p_{10}\) 和 \(p_{01}\)；
- 基线与PROPOSED的L3率；
- 行动完整率配对差标准差；
- log-energy配对差标准差；
- 设备重复CV和会话内相关；
- 每配置校准coverage；
- 数据不可用比例。

随后使用模拟而非只用正态近似：

1. 按灾种和source group重采样查询；
2. 保留配置间配对相关；
3. 模拟稀有L3和McNemar检验；
4. 模拟校准阈值与实际coverage；
5. 加入设备会话随机效应；
6. 选择达到预定功效的最小样本量；
7. 在查看正式测试结果前冻结。

如果先导风险差小于2个百分点，样本量会迅速增加。不能在先导结果不支持原效应时
仍保留乐观假设，也不能把同一查询重复运行当作补救。

## 14. 最终建议

1. 将唯一主要确认性比较定为PROPOSED与F2或S2之一；
2. 主测试集最低提高到1,200条，安全优选为1,600条；
3. `cal_op`建议800–900条，并按每配置实际接受数判断阈值是否可证明；
4. 随机解码保留3个generation seeds，确定性解码可减少；
5. 单查询资源重复先做CV先导，再在3、5或8次中选择；
6. 持续负载每策略×状态至少6个独立会话，优选10个；
7. 按约20%数据与测量损耗准备原始样本；
8. 正式规模必须在100–150条先导实验后按配对不一致率和设备方差重新模拟冻结。
