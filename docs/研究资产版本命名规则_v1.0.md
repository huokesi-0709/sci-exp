# 研究资产版本命名规则 v1.0

## 1. 版本格式

研究资产使用语义版本：

```text
MAJOR.MINOR.PATCH
```

- MAJOR：改变估计目标、主终点、正式分区、L3定义、配置含义或协议范围；
- MINOR：新增兼容字段、辅助实验、非确认性数据或方法；
- PATCH：措辞、日志、确定性缺陷和不改变分析含义的修正。

## 2. 文件命名

中文文档：

```text
主题_vMAJOR.MINOR.md
主题_vMAJOR.MINOR.csv
主题_vMAJOR.MINOR.yaml
```

机器读取数据：

```text
资产名_vMAJOR.MINOR.jsonl
资产名_清单_vMAJOR.MINOR.json
```

实验输出：

```text
设备_阶段_数据分区_方法_配置_seed_重复_vMAJOR.MINOR.jsonl
```

示例：

```text
RadxaE1_正式测试_test_op_PROPOSED_seed101_rep01_v2.0.jsonl
正式查询集_清单_v2.0.json
主要终点与假设表_v2.0.csv
```

## 4. 状态字段

数据记录必须具有以下之一：

```text
candidate
source_verified
protocol_grounded
double_annotated
adjudicated
development_gold
processed
frozen_confirmatory
```

当前400条最高状态为`development_gold`，不得标为`frozen_confirmatory`。

## 5. Manifest最低字段

每个冻结资产的manifest至少包含：

- 资产ID和语义版本；
- 创建时间；
- 上游输入路径和SHA-256；
- 当前输出SHA-256；
- schema版本；
- 代码版本或脚本SHA-256；
- 许可/公开范围；
- seed；
- 分区计数；
- 质量门禁；
- 已知限制；
- 替代或被替代资产。

## 6. 测试集变更规则

- 正式`test_op/test_ch`生成后只读封存；
- 正式结果查看后不得原地改标签、分区或查询；
- 确需修正时新增MAJOR或MINOR版本，保留旧版本和变更理由；
- Windows抽取式Smoke输出和Radxa正式输出使用不同资产ID；
- 不得用相同文件名覆盖不同模型、seed、设备状态或重复。
