## 7. Radxa交接状态

> 2026-07-29 更新：本节原始交接状态形成于首次实机运行前。当前400条已按后续
> 数据卡明确为development gold；ARM64 `llama-server`已构建并完成健康检查和
> Chat API最小验证。最新状态见
> `docs/Radxa_ZERO3W首次实机运行记录_v1.0.md`。

Windows暂存目录已经具备受控协议库、400条开发查询及六分区、文件哈希、
Radxa配置和执行脚本。当前Radxa正式执行仍有以下硬阻断：

1. `models/`中没有正式GGUF模型；
2. 当前候选Chat GGUF的裸`/completion`返回空正文，Python生成器尚未适配
   `/v1/chat/completions`；
3. ESP32-S3损坏，Radxa配置没有可用且完成校准的物理功率路径；
4. 设备型号、架构、线程和内存已初验，但系统、温度、散热、存储和调度信息
   尚未完整冻结；
5. 最终3,600条确认性数据及其正式训练/校准/测试分区尚未形成。

因此`radxa_execution_ready`仍应为`false`。ARM64服务可运行不等于设备正式实验
已完成。

复制到Radxa后执行：

```bash
cd /home/radxa/sci-exp
bash scripts/setup_radxa.sh
bash scripts/collect_device_info.sh
bash scripts/detect_power_paths.sh
```

然后放置并核验GGUF模型与`bin/llama-server`，把确认过单位的物理功率路径写入
`configs/radxa.experiment.json`和`configs/radxa.challenge.json`，启动模型服务。
完成训练输出和盲法安全判定后运行：

```bash
bash scripts/train_calibrate_route.sh
bash scripts/run_radxa_formal_tests.sh
```
