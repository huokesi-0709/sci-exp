# PROPOSED 模块消融实验方案 v1.0

**研究任务：**资源受限边缘设备上离线应急 RAG 的校准安全约束逐查询配置选择  
**适用方法：**冻结轻量文本编码器 + 查询/知识/设备状态融合 + 多任务预测 + 独立校准 + 安全约束选择  
**实验状态：**方法模块设计方案；当前已实现的 query-only 逻辑风险模型不能直接视为完整 PROPOSED

## 1. 消融实验目的

完整模型预测每个候选配置 \(c\in\{C0,C1,C2\}\) 的严重失效风险、行动效用和资源
需求，在独立校准后构造安全可行集合；无可行配置时进入 C3。

消融实验要回答的不是“删掉模块后准确率是否变化”这一单一问题，而是：

1. 该模块是否确实贡献了安全、服务质量或资源收益；
2. 收益是否来自该模块，而不是参数量、训练预算或生成器差异；
3. 该模块是否只在特定子群有效，例如 L3、证据缺口、热态或挑战集；
4. 某模块是否增加了边缘设备开销，却没有带来净收益；
5. 删除模块后，方法是否仍能满足预注册安全约束。

## 2. 完整模型和统一比较原则

### 2.1 完整模型定义

完整模型 `FULL` 包含：

```text
冻结 BGE-small 文本编码器
查询结构化特征
低成本知识/检索状态
实时设备状态
配置 embedding
配置条件门控
特征组注意力
两层浅层残差主干
风险、效用、时延、能耗、内存和回退输出头
BCE + Brier + 小权重辅助损失
资源 P95 分位数预测
独立风险校准
风险/时延/内存/最低效用安全约束
无可行配置时的 C3 硬回退
```

### 2.2 公平原则

每个消融版本必须：

- 使用相同 `train/valid/cal_op/cal_ch/test_op/test_ch` 角色；
- 使用相同查询 ID、知识库、协议版本、生成器、量化和最大输出长度；
- 保持相同可训练参数预算；删除模块后可用零向量或同维线性替代，不能让模型容量突然变小；
- 使用相同训练 steps、batch size、早停规则、超参数 trial 上限和训练 seed；
- 每个版本独立训练、独立选择 checkpoint、独立在 `cal_op` 校准；
- 不使用测试结果重新选择模块、阈值或损失权重；
- 记录路由器额外参数、模型文件大小、峰值 RSS、路由延迟和能耗；
- 失败、超时、OOM、空输出和 C3 均保留在统计分母中。

`FULL` 与每个消融版本的生成输出必须在相同
`query_id × configuration × repetition/generation_seed` 上配对。

### 2.3 结果差值

对任一消融版本 \(A\)，定义：

\[
\Delta_m(A)=m(A)-m(\mathrm{FULL})
\]

安全指标以“越低越好”为正向解释，服务质量和 coverage 以“越高越好”为正向解释；
论文中必须明确指标方向，不能只报告百分比变化。

## 3. 主消融矩阵

以下版本采用一次只移除一个关键组件（one-factor-at-a-time），是论文主消融表的最小集合。

| 编号 | 版本 | 移除/替换内容 | 验证假设 | 预期变化 |
|---|---|---|---|---|
| A1 | `-Text` | BGE-small 替换为 TF-IDF/BM25 低维表示 | 语义表示是否改善同义表达和挑战集泛化 | 近重复训练集变化小；自然改写、跨域和 OOD 的行动完整率/证据正确率下降 |
| A2 | `-QueryStruct` | 移除查询长度、否定、信息完整性等结构化特征 | 文本向量是否已足以表达显式风险边界 | L2/L3 与信息不足子集的风险召回和回退正确率下降 |
| A3 | `-Knowledge` | 移除检索覆盖、权威、时效、冲突等知识状态 | 路由是否需要知道“知识库能否支持回答” | 证据缺口、协议冲突、域外和跨灾种子集的不安全接受率上升 |
| A4 | `-Device` | 移除温度、内存、负载、电量和热态特征 | 实时设备状态是否产生独立资源收益 | 冷态平均指标变化小；热态/低内存下 P95 时延、OOM 和能耗上升 |
| A5 | `-ConfigEmb` | 配置 embedding 替换为固定 one-hot 或全零同维向量 | 配置条件建模是否改善 C0/C1/C2 的共享预测 | 配置间风险排序和校准稳定性下降；若无变化，说明 embedding 可简化 |
| A6 | `-Gate` | 移除配置条件门控，改为直接拼接 | 知识/设备状态是否应随配置改变权重 | 总体变化可能较小，但高资源 C2、证据冲突和热态子集退化 |
| A7 | `-Attention` | 移除特征组注意力，保留拼接融合 | 注意力是否提供超出门控/拼接的有效信息 | 预计收益小于 A3/A4；若多 seed 无稳定改善，应删除以降低 Radxa 开销 |
| A8 | `-MultiTask` | 只保留风险头，移除效用和资源辅助头 | 多任务是否帮助风险表示和安全选择 | 风险分类可能相近，但行动完整率、资源排序和最终 coverage 下降 |
| A9 | `-Quantile` | P95 资源头替换为均值回归 | 尾部资源建模是否必要 | 平均能耗接近；P95 时延、热态越界和资源约束违反增加 |
| A10 | `-Calibration` | 移除独立 `cal_op` 校准和风险上界 | 原始风险分数是否足以安全决策 | ECE/Brier、风险越界率和 L3 严重失效上升；可能以过度拒答掩盖 |
| A11 | `-Constraint` | 只按预测能耗/效用选择，不施加风险和资源硬约束 | 安全约束是否是净资源优化的必要前提 | coverage 或平均能耗可能上升，但不安全接受率、L3 率和 OOM 明显上升；仅作机制对照 |
| A12 | `-C3` | 无可行配置时强制选择最低成本生成配置 | C3 是否防止不可安全回答被强行生成 | 表面 coverage 上升，证据缺口、协议冲突和 L3 严重失效恶化；不作为部署候选 |
| A13 | `-GroupDropout` | 关闭知识/设备特征组 dropout | 缺失遥测/检索状态下的稳健性是否来自训练增强 | 完整输入变化小；随机缺失和传感器异常测试显著退化 |

预期变化只是方向性假设，不得在查看 `test_op/test_ch` 后改写为确定结论。

## 4. 替换型消融

替换型消融用于区分“模块本身的贡献”和“实现方式的贡献”，不与全部主消融同时
扩大到测试显著性检验。

| 编号 | 版本 | 替换方案 | 验证假设 | 评价重点 |
|---|---|---|---|---|
| R1 | `Text-TFIDF` | BGE-small → TF-IDF/BM25 + 线性投影 | 轻量词法表示是否已足够 | OOD/同义改写、路由器开销、净节能 |
| R2 | `Text-Frozen` | 冻结 BGE → 解冻最后一层 | 微调语义编码是否值得额外参数和过拟合风险 | test 泛化、参数量、训练稳定性、Radxa 编码开销 |
| R3 | `Fusion-Concat` | 门控+注意力 → 直接拼接 | 复杂融合是否必要 | 安全/质量/资源三轴和额外时延 |
| R4 | `Risk-Uncalibrated` | temperature/isotonic/conformal → valid 上固定原始阈值 | 校准是否是实质贡献而非形式步骤 | ECE、Brier、风险上界违反率、coverage |
| R5 | `Resource-Mean` | P95 pinball/Huberized quantile → log1p 均值 Huber | 分位数预测是否带来尾部保护 | P50/P95 时延、能耗越界、OOM |
| R6 | `Loss-Focal` | BCE+Brier → focal loss，所有版本重新校准 | 分类排序改善是否以概率质量为代价 | PR-AUC、Brier、ECE、L3 风险和回退率 |
| R7 | `Risk-Only` | 多任务头 → 独立风险逻辑回归/MLP | 多任务共享是否超过简单风险基线 | 风险、coverage、路由净开销和可解释性 |

R2、R6 可能改变训练容量或概率形态，必须明确标记为“替换实验”，不能与严格的
单模块删除结果混在一张主表中。

## 5. 分阶段执行方案

### 5.1 阶段一：表示与输入组

运行 `FULL`、A1、A2、A3、A4、A5。

目的：回答安全路由真正依赖哪些决策前信息。该阶段优先看：

- L3 风险和风险召回；
- `should_fallback=true` 子集的回退正确率；
- 证据正确率和协议冲突率；
- 热态/低内存/检索失败子集；
- 路由器 CPU 时间和内存。

若 A3 的变化明显大于 A1/A2，说明“知识支持状态”比更强文本语义更接近本任务的
关键机制；若 A4 只改善资源而不改善安全，应把设备状态表述为资源约束模块，而不是
风险识别模块。

### 5.2 阶段二：融合与预测头

运行 `FULL`、A6、A7、A8、A9。

目的：回答模型结构是否超出简单拼接和风险-only 模型的必要复杂度。该阶段优先看：

- 每配置风险排序的一致性；
- 校准后安全 coverage；
- 行动完整率；
- P95 时延、能耗和内存预测误差；
- 路由器额外开销是否超过节省的生成资源。

若 A7 无稳定改善，则删除注意力；若 A8 只提高资源预测但损害 L3 风险，应采用
风险与资源浅共享、独立输出头，而不是继续增大主干。

### 5.3 阶段三：安全决策机制

运行 `FULL`、A10、A11、A12。

目的：验证改进是否来自“可校准、可约束、可回退”的决策机制，而不是单纯更强的
预测器。该阶段是安全解释的核心，优先看：

- 实际 L3 风险是否超过预注册 \(\alpha\)；
- 风险上界覆盖率和越界率；
- 不安全接受率；
- C3 回退正确率与错误降级率；
- matched-coverage 下的服务质量和能耗。

A11 和 A12 即使资源指标更好，也不能被解释为优于 FULL；它们是为了展示移除安全
机制的代价。

### 5.4 阶段四：缺失和扰动稳健性

运行 `FULL`、A13 以及固定比例输入扰动：

```text
知识状态随机缺失：10%、30%、50%
设备遥测缺失：10%、30%、50%
温度/内存测量加入预注册传感器误差
查询同义改写、否定词插入、无关信息插入
```

扰动只作用于 test 的输入，不重新训练或调阈值。目的不是制造新的主结果，而是检验
路由器是否依赖脆弱的元数据捷径。

## 6. 每个版本的训练与校准流程

```text
冻结数据/知识库/模型版本
→ 仅在 train 拟合标准化和参数
→ 仅在 valid 早停和选普通超参数
→ 冻结 checkpoint
→ 每个版本独立在 cal_op 校准风险或拟合阈值
→ 在 cal_ch 检查偏移，不修改模型
→ test_op/test_ch 只运行一次
→ 同一输出审查规范下进行双人盲审
```

`-Calibration` 是唯一不做独立概率校准的版本；其他版本不能共用 FULL 的阈值。
`-Constraint` 和 `-C3` 即使违反安全门，也必须完整保留结果，不能因为不安全而从
比较中删除。

## 7. 评价指标

### 7.1 主指标

所有主消融统一报告：

1. L3 严重失效率；
2. 风险约束越界率；
3. 不安全接受率；
4. 总服务 coverage；
5. 必需行动完整率；
6. C3 回退正确率；
7. 每到达查询能耗、每安全完整回答能耗；
8. P95 端到端时延和峰值内存。

### 7.2 机制专属指标

| 模块 | 额外指标 |
|---|---|
| Text/Query/Knowledge | OOD、同义改写、协议冲突、证据缺口分层风险 |
| Device | 热态/低内存/高负载下 P95、OOM、热降频次数 |
| Gate/Attention | 特征组权重稳定性、路由器延迟、参数量 |
| MultiTask | 各任务 MAE、Brier、风险-资源梯度冲突 |
| Quantile | P50/P95 覆盖、pinball loss、尾部越界 |
| Calibration | ECE、Brier、NLL、风险上界覆盖率 |
| Constraint/C3 | 不安全接受率、错误回退率、回退原因混淆矩阵 |
| GroupDropout | 缺失率—性能曲线和最坏子集退化 |

### 7.3 统计报告

每个版本报告：

```text
FULL 与消融的配对差值
95% CI
训练 seed 间均值和标准差
按 source_group_id 的 bootstrap
按 L3/C3、灾种、查询类型和 test_op/test_ch 分层结果
```

主消融使用预注册的探索性层级和 Holm–Bonferroni 校正；不能把所有消融都当作独立
确认性主检验。当前 400 条数据是 `development_gold`，消融结果只能用于开发判断，
不能写成最终确认性测试证据。

## 9. 结果解释规则

| 观察到的结果 | 允许的解释 | 不允许的解释 |
|---|---|---|
| `-Knowledge` 风险上升 | 知识支持状态有独立价值 | 直接断言知识特征具有因果作用 |
| `-Device` 热态退化 | 状态感知有资源稳健性收益 | 断言模型能精确预测所有硬件行为 |
| `-Attention` 无差异 | 注意力在当前数据/预算下没有稳定增益 | 断言注意力机制普遍无效 |
| `-Calibration` 风险越界增加 | 独立校准对安全控制有贡献 | 断言校准能保证任意分布下安全 |
| `-Constraint` 能耗下降但风险上升 | 约束造成了安全—资源权衡 | 把低能耗解释为方法更优 |
| `-C3` coverage 上升但危险错误增加 | C3 防止了强行生成 | 把 C3 当作普通低性能模型 |
| `-Text` 无显著退化 | 当前数据下简单词法表示可能足够 | 仍然声称 BGE 必不可少 |

只有在多 seed、分层结果和置信区间方向一致时，才能把模块写成主要贡献。若消融
差异小且复杂模块增加 Radxa 开销，应优先删除该模块。

## 10. 推荐最小执行集合

若计算资源有限，先运行以下 8 个版本：

```text
FULL
-Text
-Knowledge
-Device
-Attention
-MultiTask
-Quantile
-Calibration
```

之后再运行 `-Constraint`、`-C3`、`-GroupDropout` 和替换型版本。这样仍能覆盖：

- 表示层；
- 核心知识状态；
- 设备状态；
- 融合复杂度；
- 多任务学习；
- 尾部资源约束；
- 独立安全校准。

## 11. 实施状态与停止规则

当前项目已经有 query-only 风险模型、静态资源画像和 C0–C3 运行框架，但完整文本
编码、知识状态向量、实时设备状态、门控/注意力、多任务资源头和分位数损失尚未全部
实现。消融实验必须在 FULL 可运行、输出级双审和 Radxa 资源测量就绪后执行。

以下情况触发停止增加复杂度：

- 注意力或门控在多 seed 下没有稳定安全/服务收益；
- 路由器额外能耗抵消生成配置节省；
- 复杂版本只改善 smoke heuristic，未改善盲法人工结局；
